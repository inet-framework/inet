# Native group DATA acknowledgment policy

Existing native mesh group DATA follows a multicast exchange without an acknowledgment, but its QoS Control field advertises Normal Ack. IEEE Std 802.11-2024 Table9-13 requires No Ack for the selected non-GCR group form. Receive-side 10.3.2.11 independently forbids replying to group traffic regardless of that field; correcting the producer does not authorize rejecting received policy0 frames. The [catalog](../../../../doc/project/evidence/standard/ieee80211/catalog.md#ieee80211-2024-mesh-group) records the exact sources.

G0 changes only `Ieee80211MeshMac::prepareFrameTransmission()` for a native MeshDataHeader whose type is QoS DATA and receiver is a group address. It stamps the fixed-size policy bits at the existing pre-FCS hook. Multicast sequence selection, admission, airtime and recovery already use the receiver address and have no ACK wait. No power-save state or Null subtype is needed. P1 can move the same stamping into its early preparation hook with its new content policy.

`MeshGroupForwarding.test` uses four established mesh stations with power saving disabled. A locally originated group frame is delivered at the other three stations and forwarded by two relays. The existing test checks endpoint addressing, TTL, duplicate suppression, disabled forwarding and provider removal. Added assertions inspect the actual outgoing source and relay headers: each must advertise No Ack, with one source and two relay observations. A local delivery count alone would not establish that transmitted field.

The new assertion is expected to expose the old Normal Ack field on H3. On G0, all three outgoing observations must satisfy No Ack while every existing delivery/forwarding assertion still passes. The literal field correction changes neither header length nor group-response behavior. Unit codec checks alone would not demonstrate its producer path.

The isolated debug H3 parent executes the new fixture and stops on `header->getAckPolicy() == NO_ACK` at the source's actual transmission, 0.05s/event531. Its runner exits1 with no protocol PASS; the abort retains one source packet and produces no scalar run attributes. This is the added assertion exposing the old field, not a changed declared expectation. The matching G0 build passes the complete fixture, General/run0/seed0, and finishes at0.165s/event888, exit0. Its scalar attributes confirm the configuration/run/seed. All three outgoing No Ack observations and existing forwarding assertions pass, with empty runtime stderr and no ownership/undisposed diagnostics.

Only `Ieee80211MeshMac.cc` changes among the 4995 tracked source hashes between these executions; the fixture is identical. Feature state, generated feature definitions and fingerprint store remain unchanged. Parent and candidate loader proofs select their separately pinned debug libraries. No expected result or fingerprint baseline is changed. This check establishes the bounded native group DATA correction; power transitions, Null signaling and doze remain separate stages.

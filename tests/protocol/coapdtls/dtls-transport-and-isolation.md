# CoAP over DTLS Transport Binding and Session Isolation

This document explains the production changes in commit C2 and the protocol tests verifying RFC 7252 Sections 6.2 and 9.1 (`coaps://`, default UDP port `5684`).

## Production Implementation

- **Protocol & Port Boundaries ([CoapProtocol.h](../../../src/inet/applications/coap/CoapProtocol.h)):** Defines `COAP_DTLS_PORT = 5684` without registering port `5684` in `ProtocolGroup::getUdpProtocolGroup()` so `UdpProtocolDissector` never misclassifies encrypted DTLS records on port `5684` as cleartext CoAP.
- **Endpoint Binding ([CoapEndpointBase.h](../../../src/inet/applications/coap/CoapEndpointBase.h), [CoapEndpointBase.cc](../../../src/inet/applications/coap/CoapEndpointBase.cc), [CoapEndpointBase.ned](../../../src/inet/applications/coap/CoapEndpointBase.ned)):** Adds `dtlsModule`, `CoapPeerEndpoint::sessionId`, `dtls::DtlsSocket` + `IDtls::ICallback`, `pumpOutboundQueue()` handshake gating until `established(id)`, `PacketProtocolTag` stripping before `dtlsSocket.send()` and restoration on `dataArrived()`, `sendError()` failure notification, and `onDtlsSessionTerminated()` cleanup.
- **Client & Server ([CoapClient.h](../../../src/inet/applications/coap/CoapClient.h), [CoapClient.cc](../../../src/inet/applications/coap/CoapClient.cc), [CoapServer.h](../../../src/inet/applications/coap/CoapServer.h), [CoapServer.cc](../../../src/inet/applications/coap/CoapServer.cc)):** Accepts `coaps://` (and rejects `coap://` and multicast) when `dtlsModule != ""`, defaults `peerPort` to `5684`, binds server listening via `listenOnDtls()`, and purges `pendingSeparateResponses` belonging to closed DTLS sessions.
- **Compound Modules & Feature ([CoapDtlsClient.ned](../../../src/inet/applications/coapdtls/CoapDtlsClient.ned), [CoapDtlsServer.ned](../../../src/inet/applications/coapdtls/CoapDtlsServer.ned), [.oppfeatures](../../../.oppfeatures)):** Orders `coap` before `dtls` in `CoapDtlsClient` and `dtls` (`localPort = 5684`) before `coap` in `CoapDtlsServer`, gated by feature `CoapDtls` (`-DINET_WITH_COAPDTLS`).

## Test Verification

- **Handshake, Dissection, CON/NON, Scheme & Multicast Rejection ([Rfc7252DtlsHandshakeAndExchange.test](Rfc7252DtlsHandshakeAndExchange.test)):** Verifies `coaps://host2:5684` PSK + HelloRetryRequest cookie handshake with a `3s` `handshakeOutDelay` and `2s` CoAP `ackTimeout` produces zero CoAP retransmissions while the handshake completes, outer wire packets carry the `dtls` protocol tag with port `5684` unregistered in the UDP protocol group, `CON GET` (`2.05`) and `NON POST` (`2.04`) succeed, and `coap://` / multicast / `coaps://`-on-UDP raise `cRuntimeError`.
- **IPv6 Certificate & Mutual Auth ([Rfc7252DtlsIpv6Certificate.test](Rfc7252DtlsIpv6Certificate.test)):** Verifies `CoapDtlsClient` and `CoapDtlsServer` over `StandardHost6` + `Ipv6FlatNetworkConfigurator` with `dtls.profile = "certificate"` and `clientAuthentication = true` complete `GET` (`2.05`) and `PUT` (`2.04`).
- **Session Replacement, Handshake Timeout & Send Error ([Rfc7252DtlsSessionIsolation.test](Rfc7252DtlsSessionIsolation.test)):** Using `CoapDtlsTestPeer` on `host1`, verifies that replacing an active DTLS association on the same 4-tuple purges pending separate responses (preventing leakage onto session 2) and clears the prior session's deduplication tombstones (allowing immediate reuse of `MID = 42` on session 2). Separately verifies that a `1s` handshake timeout and an oversized payload triggering `Dtls::sendError()` each emit `requestFailed` once and drain `pendingRequests` to `0`.

# IEEE 802.15.4 M1 wire-vector captures

These synthetic fixtures contain two independently specified frames: the immediate
ACK `02 00 6a e4 79` from IEEE Std 802.15.4-2024, 7.2.11, and an unsecured
version-1 DATA frame. The DATA fields are PAN 0x1234, DSN 7, AR=1, source
02-01-12-34-56-78-9a-bc, destination 04-01-12-34-56-78-9a-bc and opaque payload
de-ad-be-ef. Legacy FCF/address presence and octet order follow 7.2 and 4.5.1.

`tools/generate_ieee802154_vectors.py` writes both captures with the Python standard
library and direct polynomial division, without the INET serializer. Link type
195 carries the two-octet FCS; type 230 omits it. No capture byte was repaired or
reinterpreted from the old mixed `ieee802154.pcap`. These are wire-vector/production
tooling checks, not an over-the-air device interoperability or PHY-fidelity claim.

Regenerate from the repository root:

```sh
python3 tests/serializer/tools/generate_ieee802154_vectors.py
```

The generator prints file SHA-256 values. Scapy independently checks field layouts
and FCS; its version, command and output hashes are recorded in the model results.
`serializer_ieee802154.test` admits the captures only with exact byte preservation,
typed frame use and no whole-packet raw fallback.

# AODV remaining features

> **Kind:** design · **Status:** draft · **Seal:** none · **Owns:** — · **Stands on:** [RFC 3561](https://www.rfc-editor.org/rfc/rfc3561.html), [current model decisions](../../doc/project/evidence/model/aodv/conformance.md)

This plan defines work for the remaining AODV capabilities identified in the source review: subnet-router operation and external-network gateways, live interface reconfiguration, IPv6 multi-interface and subnet routing, the Hello Interval extension, and application notification when discovery fails. A router should be able to advertise an attached subnet, retain usable routes when one radio disappears, and tell an application when bounded discovery cannot find its destination. The [subnet authority contract](../../doc/project/design/aodv-subnet-coordination.md) resolves C9a's sequence recovery and bounded cooperation decisions before their dependent implementation.

The work is divided into independently reviewable commits. Tests and their reviewer documents travel with the behavior they establish. The starting-point assessment below is historical; current execution evidence belongs in the [implementation record](../../doc/project/evidence/model/aodv/remaining-features-results.md). Neither the plan nor a passing simulation establishes complete RFC conformance.

## Design decisions

### Keep protocol state with its owner

[Aodv](../../src/inet/routing/aodv/Aodv.h) continues to own searches, queue membership, sequence numbers, link-qualified state and precursor delivery. Use its existing `RouteKey`, `Search`, timers, operational generation and native routing-table records. Native tables remain the only source of active forwarding routes. A small retained-history store is needed only when interface deletion forces a native record to disappear before its protocol history may expire; it never forwards data. Reuse the existing recovery machinery. Shared IP packet ownership stays with the network protocol.

The choices below follow [reuse](../../doc/project/rule/architecture.md#ar-ext-reuse), [minimal design](../../doc/project/rule/quality.md#qr-design-minimal), [lifecycle](../../doc/project/rule/architecture.md#ar-life-operations) and [model detail](../../doc/project/rule/architecture.md#ar-mod-fidelity) guidance.

| Proposed addition | Owner and consumer | Why existing state is insufficient |
| --- | --- | --- |
| RREQ/RREP extension fields and encoding | AODV message definitions and serializer; Hello sender/receiver and relays | Fixed headers cannot carry the RFC's Type/Length/Data extension. Use existing chunk APIs; no change under sealed `common/packet/`. |
| Per-neighbor advertised interval | Existing link-qualified observation state; incoming-traffic refresh | A deadline alone cannot reproduce the neighbor's timeout on later data reception. Retain interval only while that observation is armed. |
| Queued failure operation | `INetfilter`, implemented by each network-protocol owner; AODV caller | Deletion and reinjection cannot both report failure and terminate the queue obligation safely. |
| Configured interface names plus live IDs/addresses | AODV; ingress, output and interface notifications | A saved pointer cannot remain valid after interface deletion. Names express desired membership; resolved IDs express current availability. |
| History of externally removed AODV routes | AODV; freshness decisions, known-host blocking and search retention | Both native routing tables can delete routes while handling an interface notification, before AODV sees that notification. Lost sequence history cannot be reconstructed from remaining routes. Retain only exact-prefix inactive history and value identities, not active routes or deleted pointers. |
| Advertised subnet authority state | AODV, keyed by exact prefix; authoritative reply generation | Learned routes and the node's host counter cannot represent a separate locally owned subnet sequence domain. |
| Subnet-router coordination contract | C9a selects the owner and required mechanism before C9 adds code | Ordinary RREPs identify a requested member and prefix, not a remotely relayed authority identity or a safe counter-transfer protocol. Election cannot be inferred from the last hop. A separate module is an option, not an established requirement. |

If C9a selects a separate coordinator, local coordination with AODV uses direct typed calls; actual communication between routers uses packets. Reuse AODV's local authority owner if coordination is small enough to belong there. A new module, interface or protocol must have a concrete responsibility that the existing owner cannot reasonably serve under [AR-ORG-CONTRACTS](../../doc/project/rule/architecture.md#ar-org-contracts).

### Wire extensions and observation

Implement RFC 3561 sections 9 and 9.1 without changing the existing base-header bytes. The Hello Interval extension is Type 1, Length 4, with a uint32 interval in milliseconds. Store bounded Type/Length/Data records on RREQ/RREP so relays preserve extension bytes. Parse exactly the current UDP payload, not following packet data. Validate the complete message before route updates, binding learning or observation refresh. Proposed receiver policy: accept at most one positive Type 1 interval; reject duplicate Type 1 records, Type 0, invalid lengths, truncation and unsupported types 128–255. Preserve and ignore unknown types 2–127. The latter handling is the selected model policy for the RFC's incompletely specified extension rules. Only a valid Hello uses Type 1 to set the neighbor's interval. On an ordinary RREQ/RREP, preserve it without interpreting it; the ordinary validated-traffic refresh still applies to an already armed neighbor.

This requires changing the actual receive path, not just the serializer. `ensureRouteForDatagram()` currently calls `observeIncoming()` before classifying incoming control, and `processPacket()` learns bindings before dispatch. Exclude reserved AODV UDP traffic from the early data-observation refresh, including malformed reserved control. Refresh validated AODV traffic after complete parsing in `processPacket()`; keep ordinary data and native ND observation in the hook. A malformed extension must not renew a previously armed deadline through the earlier hook. Treat parser errors as rejected input, not fatal simulation errors, and preserve valid data/ND liveness controls.

Proposed compatibility policy: append the interval whenever Hello transmission is enabled, including for the default interval. Without the extension, reception retains the existing fallback to the local configured interval. With it, use `allowedHelloLoss * advertisedInterval` for that neighbor's observation timeout. Update both Hello arming and `observeIncoming()` refresh to use the stored interval; refresh must not revert to the receiver's local setting. Hello reception uses the same interval when deriving its minimum route lifetime, independently of sequence acceptance. Keep advertised route lifetime and neighbor observation separate. Disabling observation, expiring a neighbor and clearing/restarting the module remove the retained interval with its deadline. Positive stale-sequence Hellos may update observation without replacing fresher route state, as in the current model.

This changes Hello packet length when enabled and requires release documentation. Avoid imposing a new integral-millisecond restriction on the simulation parameter merely because the wire field has millisecond resolution. Keep the configured timer period, advertise its ceiling in whole milliseconds and use at least `allowedHelloLoss * encodedInterval` as the emitted Hello lifetime. This is an explicit conservative encoding policy: the receiver's estimate must not be shorter than the configured nominal period because of rounding. Use that same encoded observation bound consistently for Hello-related active-route and deletion-retention minimum checks at start. Reject a nonpositive interval or an interval/derived lifetime whose conservative encoding cannot fit the positive uint32 millisecond range. Validate multiplication and simulation-time bounds on reception before arming a deadline; do not rely on a serializer truncating overflowing values.

### Failure reporting belongs to IP

Add a distinct proposed `INetfilter::failQueuedDatagram(const Packet *)` operation. The name and signature are proposed; its contract is fixed: find an existing queued obligation by pointer identity, detach it before callbacks, report destination unreachability through the owning network protocol's existing error path, and dispose of the original once. A missing obligation is a no-op, as for existing lifecycle-safe disposal. AODV must not remove headers, take ownership of borrowed packets or call concrete IPv4/IPv6 ICMP modules.

[Ipv4](../../src/inet/networklayer/ipv4/Ipv4.cc) reports Destination Unreachable / Host Unreachable; [Ipv6](../../src/inet/networklayer/ipv6/Ipv6.cc) reports Destination Unreachable / No Route. Reuse native ICMP suppression and local-delivery paths, including their handling of a still-unspecified source on a locally queued packet. Verify both unspecified-source and explicitly bound local sockets through real UDP indications, with the original quoted destination/ports. Native suppression may prevent an indication; “exactly one” applies to eligible UDP datagrams, never ICMP-error, multicast or broadcast probes. [NextHopForwarding](../../src/inet/networklayer/nexthop/NextHopForwarding.h), the other in-tree provider, implements this new operation as silent disposal through its existing API because it has no IP error protocol. Document that fallback; do not add a new transport error protocol to it. Existing silent-drop API and callers remain available.

AODV calls the new operation only for terminal originating-discovery failure. Distinguish timeout/exhaustion from stop, crash, interface reconfiguration and output-constraint rejection. Local-repair failure retains its existing RERR/queued-transit policy. Detach the search and every FIFO first, then perform callbacks with the existing lifecycle generation checks.

### Interface identity and IPv6

Keep the configured primary identity stable during secondary-link changes. For IPv6, use the interface's existing preferred address when it is usable non-link-local unicast; reject a link-local-only or otherwise unsuitable preferred identity with a diagnostic rather than invent another address-selection algorithm. Link-local addresses alone cannot identify a multi-hop originator. Selected interfaces must have distinct identities of one address family. Link-qualified neighbors still include the interface ID. Reuse native ND and join/leave control multicast on every participating link. Do not charge physical copies as separate searches or introduce extra random draws per copy.

On secondary down/removal/address change, invalidate current routes through that link, remove ACK/blacklist/binding/observation and delayed-output state for it, and notify usable precursors through surviving links. Recheck queued packets and keep searches that can still progress; when no selected link is usable, dispose of old queued demand silently and suspend new discovery. Re-adding a deleted interface resolves its new ID and usable address. A down/up event may retain the same ID, but must rebuild bindings and observation instead of reviving stale deadlines. New AODV-dependent demand for a suspended router is dropped silently rather than retained indefinitely; valid independent/manual forwarding and native ND remain available.

During a primary address loss/change, cancel old-identity work, clear owned routes and enter the existing recovery hold before advertising the replacement identity. If the configured primary is unavailable, suspend AODV until it is usable instead of silently selecting a different primary. This includes AODV-dependent demand arriving after suspension, not just packets already queued when the interface changed. Primary link down/up follows the same conservative recovery policy even if its address is unchanged. Initial start retains the existing validation requirement for usable configured interfaces; suspension handles changes after a successful start rather than silently accepting an invalid initial configuration.

Use existing interface notifications at their real emission point. In particular, deletion notification occurs while the object is still available; extract needed IDs and addresses then, and retain no deleted pointer. Cancel or reject sends already prepared with old source/interface tags. Resolve configured names again when creation/state/configuration notifications establish a usable replacement, not at an assumed construction stage. Keep notification subscriptions across ordinary stop/start and ignore behavioral events while down; destruction unsubscribes before referenced modules disappear. Crash and stop cancel pending protocol work. Do not detach subscriptions on stop without reattaching them on start. Dynamic creation covers a matching replacement name, not arbitrary hot changes to the configured name set.

Account for native-table listeners as well as the interface object. [IPv4](../../src/inet/networklayer/ipv4/Ipv4RoutingTable.cc) removes matching routes and emits `routeDeleted` while the record is still readable; [IPv6](../../src/inet/networklayer/ipv6/Ipv6RoutingTable.cc) does so on interface deletion and down. AODV must consume that notification without depending on listener order. For an externally removed owned route, copy its exact key, sequence/validity, last hop count, retention deadline and old link identity by value. Capture precursor recipients before the record is freed. Apply the existing expire-if-due rule first: a flag still marked active at its passed lifetime does not turn idle expiry into confirmed-loss counter advancement. For a still-active route, advance a known counter once, make it inactive and start deletion retention; an already inactive record retains its counter and existing retention obligation. AODV's own expiry/cleanup deletion paths must not create replacement history, and callbacks must not insert routes into a native table while it is iterating deletions.

C6 adds one coalesced same-time reconciliation event. Route-deletion/interface callbacks capture value snapshots and make removed IDs unavailable synchronously, then schedule reconciliation; they do not transmit notifications from inside a native-table mutation. This matters because `queueRouteError()` sends immediately for zero jitter, potentially before the primary-interface deletion callback has run. At reconciliation, finish live-selection cleanup and combine each affected link's required error records/precursors before calling the existing RERR partition/budget path. Do not duplicate notifications when both route and interface callbacks report the same loss. The event is canceled on lifecycle cleanup. Resolve interfaces by live ID before every pointer use while reconciliation is pending; do not retain a deleted interface until the event runs. This event boundary needs no extra random draw or protocol-specific processing delay.

Route freshness and retained-prefix lookup must consult this inactive history when a native owned record is absent. Audit `createRREQ()`, message-specific RREQ/RREP/Hello acceptance, generic neighbor refresh, retained search authority and data eligibility together: changing only one lookup would let another path recreate a stale host. A known deleted host must still block a covering AODV aggregate; an unknown placeholder must not. Preserve active independent/manual forwarding precedence, as in the current native-route selector: retained AODV knowledge must not invalidate or veto an otherwise eligible non-AODV route. An accepted same-key AODV update installs a normal native route and consumes that history; rejected stale updates leave it intact. Use the existing expiry timer and search-retention rules, including extending knowledge retained by pending demand, rather than another timer or an unbounded permanent cache. Stop/crash and the C7 primary-identity reset clear this learned history. Tests must verify cleanup and freshness, not just the absence of dangling pointers.

For delayed control, an interface ID remaining valid is insufficient after readdressing. At actual send, verify the packet's prepared source still equals the selected current identity on that output; discard old-address packets. C7 advances the existing operational generation when replacing the primary identity and uses the existing recovery timer/deadline without calling lifecycle start/stop handlers on a still-operating module. The wildcard-bound UDP socket can remain open for a same-family address change; adjust memberships for actual link changes rather than rebinding solely because the source address changed. Live switching between IPv4 and IPv6 is outside this interface-reconfiguration feature.

For IPv6 prefix encoding, preserve the existing seven-bit field: prefix zero means host, nonzero values 1–127 are aggregates, and `/128` host routes use zero. Reject `/0`. Extend exact-prefix acceptance and data selection rather than introducing a parallel IPv6 route owner. Preserve host-only RREQ sequence floors until a separately justified wire convention can distinguish host and subnet counter domains.

### Subnet authority and election need an explicit cooperation profile

RFC 3561 sections 7 and 8 require a subnet-owned counter, lowest-address subnet-router election and consistent external-subnet semantics. They do not supply enough wire machinery to implement safe distributed election and counter handover merely by comparing received RREP source addresses. This plan therefore includes the coordination work explicitly.

A candidate coordination profile is a configured set of routers exchanging candidate identity and subnet sequence state over a common attached subnet. C9a must compare that with reuse of existing mechanisms and select the smallest supported profile. It must not add a separate control network, public interface or coordinator module merely to fit this sketch. Explicitly configured single-router authority needs no election traffic. In a multi-router profile, candidates compare actual router addresses, not RREQ target members.

Before C8, C9 or C10 implementation, C9a establishes the [subnet authority contract](../../doc/project/design/aodv-subnet-coordination.md). It selects an opt-in configurable mandatory prefix-floor TLV, exact-domain floor adoption/relay propagation, and candidate announcements over a separate UDP endpoint. Election assumes trusted finite candidates, a common connected subnet, bounded reliable delivery and fail-stop crashes. It does not guarantee exclusion during arbitrary partitions. False-to-true eligibility restarts qualification, and unknown counters adopt their first known floor before serial comparison. Implementation and runtime evidence must establish these chosen contracts; the document alone is not completion evidence.

In particular, waiting `DELETE_PERIOD` alone is not a counter-handover proof: continued demand may retain upstream knowledge longer. Transfer one subnet counter domain; never compare an independent replacement router's host counter against it. Retain the existing conservative treatment of ambiguous RERR identities and document that the wire has no prefix length. No claim of arbitrary prefix-identity reassignment is made.

Single-router authority in C8 uses a proposed `advertisedSubnets` XML parameter, default `xml("<subnets/>")`. Its root is `<subnets>` and each child names a canonical prefix and exact attached-interface name, for example `<subnet prefix="192.0.2.0/24" interface="eth0"/>`. Proposed attachment rule: at actual start, the configured prefix must be contained in a connected IPv4 prefix assigned to that interface, or in an IPv6 prefix advertised as on-link by that router on that interface. Containment includes equality; merely containing the router's own address is insufficient. This permits exporting a `/25` inside its attached `/24` but rejects exporting a `/16` based only on that `/24`. Require the same address family as this AODV instance. No subnet is inferred for export merely because a route exists. Host-only entries and `/0` are rejected; IPv4 aggregates are `/1`–`/31`, IPv6 aggregates `/1`–`/127`. Duplicate entries are rejected; overlapping entries use longest-prefix match with independent counters.

Authoritative replies are on demand, retaining the requested member address and setting the prefix size. There are no unsolicited RREP floods. A subnet counter is distinct from `sequenceNum` and uses existing 32-bit serial arithmetic. The current received-subnet profile treats RREQ floors as host knowledge: an authority may answer an unknown-floor request, including D=1, but must not compare a known host floor with an unrelated subnet counter. C9a must define how that rule extends to authoritative subnet recovery before C8 is implemented. A freshly reachable authority must be able to satisfy retained same-subnet freshness requirements after upstream invalidations; incrementing a local counter by one on each reply is not a sufficient recovery algorithm because repeated failed transit packets can advance upstream knowledge several times.

The C9a contract must explain how an originator communicates the relevant subnet identity and sequence floor, how relays preserve that meaning, and how the authority obtains a safe counter without importing an independent host floor. Evaluate the existing wire format first; if additional signaling is necessary, identify it as an explicit model extension, define its compatibility behavior and add its implementation/tests to C8. Do not assign an unregistered extension number as if it were standardized. The current host-only floor profile remains the behavior of C5 and legacy peers; any changed subnet mode must document what mixed peers can establish. A known independent host floor may still require a host-specific answer rather than an aggregate reply, but retained aggregate demand must not be dismissed as an expected discovery failure merely to bypass the missing recovery mechanism.

The candidate same-instance policy retains configured-prefix counters across ordinary stop/start, simulated crash/start and primary-identity changes while clearing active advertisements, timers and precursor obligations. C9a must decide and justify that persistence model separately from actual state loss and cold module creation. It must define how lost authority history is recovered before advertisements resume. Preserve only finite configured-prefix history, not deleted learned routes. A recovery wait alone cannot reconstruct a missing subnet counter from host-only request floors; ordinary host reboot behavior cannot be copied as a proof for subnet authority.

Locally attached member forwarding must bypass MANET rediscovery for this explicit export, including connected routes on non-selected interfaces. A nonexistent member produces native ICMP without invalidating the aggregate. [IPv4 ARP timeout](../../src/inet/networklayer/ipv4/Ipv4.cc) currently drops pending packets silently, so C8a supplies that missing IP behavior first. [IPv6 ND](../../src/inet/networklayer/icmpv6/Ipv6NeighbourDiscovery.cc) already emits Address Unreachable and remains a control. A new upstream member-negative cache is outside these seven features; preserve aggregate reachability and deliver the existing ICMP indication without adding an unbounded host-state store.

The infrastructure-router mode in C10 reuses subnet authority and the cooperation profile selected by C9a. Its separate proposed `externalSubnets` XML parameter names canonical prefixes and output interfaces; it defaults to `xml("<subnets/>")` and uses the same syntax/range rules. A covering route must cover the entire configured prefix and use the named external interface, not merely match one member. Ignore AODV's own routes in this decision to prevent recursive reachability. Require an up interface and a currently eligible native non-AODV covering route before answering. C10 checks that condition at reply preparation, actual control send and data forwarding as well as observing `routeAdded`, `routeChanged` and `routeDeleted` notifications. A well-formed export without such a route is dormant, not a startup error: routes may appear after startup.

Do not withdraw inside a native route-change callback. IPv6 also emits `routeDeleted` immediately followed by `routeAdded` while updating an advertised prefix in place, so the first signal does not necessarily mean reachability was lost. Extend C6's coalesced same-time reconciliation event to evaluate the final authority-eligibility set after the current routing-table operation. This event boundary is justified by that existing notification contract; it introduces no random draw. Keep only one pending reconciliation and retain no signaled route pointer. The synchronous checks before preparing/sending a reply or forwarding data prevent the event delay from authorizing stale output. C8 adds authority eligibility to that owner; C10 adds external-route triggers, without another timer for the same job.

For both attached and external authority, keep interface-qualified precursors in the exact configured-prefix authority record. Add a precursor at actual authoritative-reply send, using the outgoing next hop/interface; a suppressed or canceled reply creates no new dependency. When reachability is lost, stop answering, advance the authority's subnet counter once for that transition, mark the advertisement unavailable and send ordinary RERRs naming the normalized prefix to its usable saved precursors through the existing budget/partition logic. Do not advance repeatedly for a burst of route-change notifications while already unavailable. If a covering replacement route still exists, no reachability-loss transition occurred. Peers may retain stale information until notification or expiry; this plan does not promise instantaneous global withdrawal. A restored export must advertise a counter consistent with retained history under the C9a recovery contract.

For attached exports, interface down/removal or loss of the required containing prefix withdraws authority just as loss of external route eligibility does; a missing individual member does not. After a usable interface/prefix returns, revalidate and make the export eligible again without resetting its sequence history. Preserve manual routes and the old `gatewayAddress` behavior when the parsed export lists have no entries. Reject nonempty `gatewayAddress` combined with one or more entries in either export list rather than leave two competing gateway rules. The default `<subnets/>` element is an empty list, not a conflict merely because its XML pointer exists. Exact duplicates across attached/external exports are rejected; overlapping distinct prefixes retain longest-prefix selection. External routing protocols are consumers/providers of ordinary routes, not part of this AODV implementation.

## Commit series and verification

Implementation review added three prerequisite corrections: declare AODV's existing graceful-stop timing parameters before lifecycle callers; expose native expiry through `IRoute` before external-route consumers; and separate the coordination wire format, serializer and introspection support from its first production sender. The latter is C9b below. Each correction has its own commit; test/evidence fixes are folded into their owning commits. Independent feature commits may appear in a different linear order when all declared dependencies remain before their callers.

### C0 — Aodv: declare graceful-stop parameters

The existing stop implementation reads undeclared `stopOperationTimeout` and `stopOperationExtraTime` parameters. Declare the standard two-second timeout and negative extra-time defaults, preserving immediate completion after socket closure. The existing `AodvLocalRepairShutdown.test` exercises the base module contract; new lifecycle subtypes override values without redeclaring parameter types. Keep this correction before the new lifecycle fixtures.

### C0a — IRoute: expose native expiry

Add a pure read-only `getNativeExpiryTime()` query to `IRoute` and all three providers. Zero means no native expiry; a finite absolute time is inclusive, matching native IPv6 lookup. Protocol metadata lifetime remains independent. `RouteExpiry.test` checks generic dispatch and the C10 finite-expiry protocol case establishes the consumer behavior. Add the custom-provider migration note and incompatible API release note before C10.

### C0b — Tests: normalize inherited fixture endings

The upstream PR also includes the earlier correction series. A standalone formatting preparation after this plan removes only extra terminal blank lines from its AODV `.test` files, so the complete PR passes whitespace checks. It changes no assertion text, generated support source or runtime configuration and remains separate from feature changes.

### C9b — Aodv: define coordination packet support

Define the separate coordination chunk, serializer, payload protocol, dissector and printer before C8/C9. `AodvSubnetIntrospection.test` starts with independent IPv4/IPv6 byte vectors and checks the registered inspection paths. The preparation enables no packet sender by itself and is separate from C9's candidate state machine.

Every entry below specifies future work, including writing tests and reviewer documents. All new test names are proposed and absent today. A path containing `{Case}` expands to one concrete `.test` file per case listed in that entry, for example `Rfc3561HelloIntervalExtensionDifferentIntervals.test`; the selector must include every expansion. Each file uses one independent topology/configuration. Rejection cases get their own initialization-error fixture rather than stopping a multi-case run at the first error. Existing tests are controls unless explicitly identified otherwise; none has been executed for this plan. Later entries assume only the stated changes in earlier entries. Keep every commit buildable and independently explainable under [PR-SERIES-BUILDS](../../doc/project/rule/pull-request.md#pr-series-builds).

For C1–C10, no existing test establishes the whole new capability. Each entry names the nearest existing controls where available and the exact new families that close the gap. C9a is a design-document commit placed before C8; it must resolve its questions and update C8/C9/C10 before those conditional implementation entries can be executed. Identifiers remain stable even though the prerequisite now appears earlier in the series.

### C1 — Aodv: support the Hello Interval extension

**Dependencies:** none. Change `AodvControlPackets.msg`, `AodvControlPacketsSerializer.{h,cc}`, `Aodv.{h,cc}` and relevant packet dissector/printer consumers found by symbol search. Generate message code through the build. Append/parse extensions and retain each armed neighbor's interval as described above. A neighbor sending Hellos every two seconds must not expire according to a receiver's one-second setting.

Write the `tests/protocol/aodv/Rfc3561HelloIntervalExtension{Case}.test` family with cases `DifferentIntervals`, `LegacyFallback`, `DataRefresh`, `Rounding`, `Bounds`, `Malformed`, `UnknownExtensions`, `Forwarding` and `Restart`. Use native UDP/IP and two independently attributed neighbors; vary one interval while holding the other fixed. Assert extension bytes against the RFC layout, actual timeout boundaries, absence of malformed-input binding/route/observation changes, preserved extension data on forwarding and removal of interval state on restart. `Rounding` sends nominal 0.75 ms and 1.5 ms intervals and asserts encoded estimates of 1 ms and 2 ms, sufficient advertised lifetimes and no deadline shortened by rounding. Bounds cover wire zero, UINT32_MAX and multiplication overflow. Parent behavior lacks the extension and uses the local interval; these are source-based expected differences to verify, not executed parent failures. Serializer round trips supplement an independent byte oracle. Add `tests/module/AodvHelloIntervalValidation{Case}.test` with Hello transmission enabled for `Zero`, `EncodedIntervalOverflow` and `LifetimeOverflow` rejection configurations.

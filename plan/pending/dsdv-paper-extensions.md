# DSDV dissemination, failure feedback and base-station routes

> **Kind:** plan · **Status:** draft · **Seal:** none · **Owns:** — · **Stands on:** [source profile](../../doc/project/evidence/protocol/dsdv/standards.md), [planning procedure](../../doc/project/guide/write-an-implementation-plan.md)

Improve DSDV in four steps: fairly distribute sequence-only updates, react to MAC failure notifications, adapt periodic full-dump timing, and let a base station advertise access to an external network. Each step includes its implementation, direct protocol tests and a reviewer document. This file proposes the work; it does not report implemented features or successful runtime validation.

## Scope and ownership

Keep `DsdvTable` as the sole owner of route freshness, successors, advertised state, send obligations and incremental selection. Keep `Dsdv` responsible for UDP, interface and routing-table integration, timer scheduling and configuration. Extend these existing owners rather than introduce another routing protocol, generic scheduling framework or new MAC signal. Retain the names `RouteEntry`, `routeEntries` and wire tuple `DsdvEntry`.

Ordinary routers continue to use one bidirectional ad hoc IPv4 interface. A base station may additionally use one explicitly configured external interface. This plan supports one configured base-station identity per DSDV domain. Automatic gateway discovery/election, simultaneous gateways, arbitrary prefix propagation, MAC-layer DSDV, proxy ARP, IPv6 and security remain follow-up work. Supporting several independently selected gateways would require a separate forwarding-loop analysis; their destination sequence numbers cannot be compared as one default destination.

Reuse the existing timer objects and lifecycle handlers for C1–C3. C4 adds one coalesced route-reconciliation event because IPv4 route notifications can occur inside a routing-table iteration; its reason and lifetime are specified below. Cancel scheduled work on stop, crash and ad hoc interface loss; retain sequence and withdrawal floors according to the current restart contract. Reset fairness and adaptation history on a fresh active session. No new background work may execute while DSDV is inactive. Keep subscriptions across stop/start, ignore failure/route hints while inactive and unsubscribe on destruction. Module recreation without persistent sequence state remains outside the supported contract.

Follow [minimal design](../../doc/project/rule/quality.md#qr-design-minimal), [reuse](../../doc/project/rule/architecture.md#ar-ext-reuse), [lifecycle operations](../../doc/project/rule/architecture.md#ar-life-operations), [commit planning](../../doc/project/rule/pull-request.md#pr-series-plan) and [protocol-test planning](../../doc/project/rule/testing.md#tr-plan-protocol). None of the proposed source paths is currently sealed. Do not change the sealed packet subsystem to implement these features.

## C1: Fair selection of sequence-only entries

When an incremental can fit one optional entry but three destinations have newer sequences, successive qualifying sends must offer all three a turn. Today, address-order traversal can repeatedly send the first destination because the comparison baseline changes only on a full dump.

Add one optional-selection cursor to `DsdvTable`. After collecting required changes exactly as today, traverse optional candidates cyclically starting after the last optional destination actually submitted. Advance the cursor only when an optional entry is included. Do not create a trigger merely to drain sequence-only changes, and do not move the full-dump baseline after an incremental. A full dump or session reset clears the cursor; a cursor whose destination disappeared still works as an address ordering boundary. This needs no per-destination queue or duplicate snapshot.

Required changes and corrective obligations always take precedence. Zero spare slots leave the cursor unchanged. Required overflow still escalates to a fragmented full dump; optional overflow never does. Select a destination at most once per packet even when cyclic traversal wraps. For a stable set of N optional entries between full dumps and at least one spare slot on each qualifying incremental, every entry is sent within N such incrementals. This guarantee is conditional on send opportunities, not a new wall-clock deadline.

**Files and consumers:** `DsdvTable.h/.cc`; extend existing `tests/unit/DsdvDissemination.test`. `Dsdv::sendAdvertisement` remains the production caller. No wire or NED change is needed.

**Protocol tests to write:** `tests/protocol/dsdv/DsdvIncrementalFairness.test`. Use a router under test, a UDP update injector and a silent listening receiver, with real socket delivery and a 48-byte DSDV payload budget (two version-1 entries). Observe the first randomized periodic callback, then seed more than two required destinations to obtain an overflow full dump and establish the complete baseline. Choose a long periodic interval so the remaining test finishes before the next periodic callback. Supply three same-metric sequence changes. Change a fourth destination's metric so it remains different from the full baseline and consumes one required slot on each subsequent incremental. After its settling deadline, provoke further sends with stale odd-sequence withdrawals for that fourth destination, requiring corrections without changing the three optional candidates. Observe decoded receiver-side incrementals and require all three optional destinations before any repeats. Assert the required destination is always present, datagrams fit, no destination occurs twice and optional excess causes no full dump. Add zero-spare-capacity and full-dump-reset cases. Use fixture-owned deterministic update injection; do not call `prepare()` directly as the protocol evidence.

**Before/after and limits:** current code repeats the lowest-address optional entry in the controlled sequence; rotation makes the bounded fairness assertion pass. Unit cases additionally cover candidate insertion/removal and wraparound. These tests do not promise fairness under continuous required-only traffic or packet delivery despite loss.

**Reviewer document to write in C1:** `tests/protocol/dsdv/DsdvIncrementalFairness.md`, explaining the baseline, packet capacities, sequence timeline, expected optional order and receiver assertions. Include the test topology and distinguish local submission from remote receipt.

## C2: MAC failure feedback

If a data frame exhausts its MAC delivery procedure before the neighbor timeout, DSDV should withdraw routes through that next hop immediately. Section 3 permits link-layer detection as an alternative to silence-based detection. Treat the existing MAC's `linkBrokenSignal` as the failure decision; do not add another configurable counter or change MAC retry rules. The resulting inference can be premature under transient interference, which is why timeout-only behavior remains selectable.

Add `useMacFailureFeedback = false` to `Dsdv.ned`. When enabled, subscribe at the containing node to the existing `linkBrokenSignal`. The [AckingMac timeout](../../src/inet/linklayer/acking/AckingMac.cc) and [DCF retry-limit path](../../src/inet/linklayer/ieee80211/mac/coordinationfunction/Dcf.cc) already emit this signal with a borrowed failed `Packet`. Both MACs obtain their outgoing receiver from `MacAddressReq`; the handler must use that failed transmission's receiver and emitting interface, rather than look up the packet's ultimate destination in the current routing table.

Dispatch `receiveSignal` by signal identifier before casting its value: interface changes, link failures and C4 route notifications carry different object types. Filter failures by the emitting module's ancestry under the configured interface module, not by a possibly stale incoming-interface tag on a forwarded packet. Read the failed packet's retained `MacAddressReq` receiver and `NetworkProtocolInd` IPv4 header without modifying or retaining the borrowed packet. [AckingMac::encapsulate](../../src/inet/linklayer/acking/AckingMac.cc) and [Ieee80211Mac::encapsulate](../../src/inet/linklayer/ieee80211/mac/Ieee80211Mac.cc) retain the MAC request, and [findNetworkProtocolHeader](../../src/inet/networklayer/common/L3Tools.cc) reads the network-header indication even when the packet front and `PacketProtocolTag` identify a MAC frame. Ignore non-IPv4, non-unicast, missing-metadata and inactive-module cases.

Resolve the failed receiver through the existing [IArp::getL3AddressFor](../../src/inet/networklayer/contract/IArp.h) contract. Add `arpModule = default(absPath("^.ipv4.arp"))` and a `ModuleRefByPar<IArp>`, resolved only when feedback is enabled. If reverse resolution returns no valid IPv4 neighbor, leave timeout processing active. Do not initiate ARP from a failure callback or infer the receiver from the current route to the final destination: that route may already use another successor. This profile assumes ordinary local ARP with one ad hoc IPv4 identity per neighbor MAC. No concrete MAC-class dependency is needed. The signal is a failure hint, not proof of physical disconnection: for example, HCF also emits it after an internal collision exhausts retries. The planned direct integration tests target AckingMac and ad hoc DCF; they will not establish general HCF or other-MAC support.

Add a table operation for loss of a named neighbor. Reuse it from expiry and MAC feedback: remove the neighbor's liveness entry, invalidate every finite route whose current successor is that neighbor, preserve unrelated successors, and reuse `invalidate()` for odd sequence, infinity and urgent send obligations. Repeated hints must not repeatedly increment already-invalid sequences. Synchronize owned IPv4 routes and schedule the existing advertisement timer at the current simulation time; no settling delay applies. A later stale queued-frame failure cannot invalidate a route that has switched to a different next hop.

**Files and consumers:** `Dsdv.h/.cc/.ned`, `DsdvTable.h/.cc`; declarations/imports for `IArp`, packet tags and existing signals. Reuse the node signal mechanism illustrated by [Aodv::receiveSignal](../../src/inet/routing/aodv/Aodv.cc), but do not copy its current-route inference. No IEEE 802.11 implementation change is planned.

Establish routes and populate the ARP cache, then separate the next hop while keeping its interface up and the observer in range of the router under test. Send unicast data before the long neighbor timeout. Require a real MAC failure signal, removal of all dependent owned routes, unchanged unrelated routes and observer receipt of an odd/infinite withdrawal before that timeout. The disabled case must retain the route until ordinary expiry. Add a controlled UDP update that switches one destination to the observer before an old queued frame fails: the failed receiver remains the old next hop, so the switched route must survive. Cover repeated hints, non-IPv4, broadcast and unresolved-receiver hints by extending `tests/module/DsdvScheduling.test`, and stop/start with pending timers through `tests/module/DsdvLifecycle.test`. The latter tests consumption of an existing MAC contract, not MAC standards conformance. For the C1-parent comparison, omit only the new feedback parameter assignment and use observations available on both revisions: the real MAC failure, owned routes and version-1 withdrawal packets. ## C3: Adaptive periodic full dumps

The current periodic interval is fixed, while required-entry overflow already forces a full dump. Add an opt-in adaptation policy that lengthens quiet intervals and shortens them after significant route churn, while accounting for the bytes a full dump costs. This models the paper's qualitative guidance without claiming to reproduce an unspecified paper formula or measure the whole channel's occupancy.

Add `adaptiveFullDump = false`, `minFullDumpInterval = fullDumpInterval`, `maxFullDumpInterval = 2 * fullDumpInterval` (both seconds) and `fullDumpBitrateBudget = 11200bps`. The existing `fullDumpInterval` is the initial interval; require finite positive bounds with `min <= initial <= max` and a finite positive bitrate budget when adaptation is enabled. The proposed budget equals one 1400-byte payload per second; it is a model default, not a paper recommendation. With adaptation disabled, do not resolve additional dependencies or evaluate adaptive expressions, and preserve the existing timer path, startup phase and random draws exactly.

`Dsdv` owns the current interval. `DsdvTable` counts significant selected-route transitions where they occur: new reachability, finite-to-infinite withdrawal, and metric or successor changes. Count received changes and local expiry/MAC invalidations once each; duplicates, sequence-only refreshes, periodic self-sequence advances and corrective resends without a selected-route change do not count. At session start, configure the counter's limit from the computed entry capacity K when adaptation is enabled, or zero to disable collection. Saturate at that limit, since the policy only distinguishes zero, below K and at least K. The periodic callback consumes and resets this history once. Reset it after startup table initialization; subsequent neighbor discovery belongs to the first observation window. Keep the counter and its limit with the table rather than add transition-result records to every public method or retain another route snapshot.

At each periodic callback, advance the self sequence and submit the full dump as today. Let I be the current interval (initially `fullDumpInterval`), K the datagram entry capacity, C the consumed significant-change count and B the submitted full dump's encoded DSDV payload bytes, summed over fragments. The proposed policy is:

1. If C is zero, propose `2 * I`; if C is at least K, propose `I / 2`; otherwise retain I.
2. Raise the proposal to at least `8 * B / fullDumpBitrateBudget`, then clamp it to the configured minimum and maximum. Implement doubling/halving with bound-aware comparisons so intermediate calculations cannot overflow or produce a scheduled interval below one simulation tick.
3. Store the selected interval as I and schedule the existing periodic timer with I plus the existing jitter draw. Consuming the counter already reset its history for the next window.

The threshold K ties the shortening decision to one packet's worth of significant transition events; these events need not be distinct destinations or an exact estimate of the next incremental's size. This is a deliberately bounded heuristic, not a congestion controller. For example, with I = 1 s, min = 0.5 s, max = 4 s, K = 2, B = 80 bytes and a 11200 bps budget, C = 0 chooses 2 s and C = 2 chooses 0.5 s. At a 320 bps budget the byte-cost floor is 2 s; at 128 bps it is 5 s, so the 4 s maximum wins and the budget is not met.

The bitrate budget is a best-effort target for periodic DSDV payload overhead, not a guarantee on total control traffic, UDP/IP overhead or PHY airtime. The maximum interval and urgent traffic can prevent meeting it. Report actual bytes and interval rather than suppress withdrawals to meet a budget. Add `fullDumpIntervalSelected`, emitted once at each adaptive periodic callback with the selected interval in seconds, with a vector statistic and an inspector expression for I. Extend `sendAdvertisement` to accumulate its per-packet payload lengths and return that sum as B; it currently returns void, so this is a small caller/result change without retained history. Do not prepare the table twice, since preparation consumes send obligations.

Triggered sends, settling deadlines, corrections and required-overflow full dumps remain on the existing advertisement path. They neither reset the periodic timer nor advance the self sequence, preserving periodic origin freshness even under repeated triggered dumps. Continue to advance the self sequence once per periodic callback, never once per fragment. Adaptation adds no timer and no random draw.

Keep the existing requirement that timeouts be positive. Do not reject a receiver merely because its own sending interval exceeds its receive timeout: expiry depends on its peers' broadcasts. For loss-free acceptance fixtures, choose each receiver's neighbor timeout above the largest peer sending interval plus peer jitter and a documented delivery allowance L; choose its destination timeout above that gap plus the largest applicable settling cap and L. Include fixed-period peers when calculating this bound. The local module cannot validate a domain-wide timing contract from its own parameters, so document the assumption without adding interval negotiation or another global parameter. Loss and unbounded latency can still cause expiry; the fixture inequalities are not a general correctness guarantee.

**Files and consumers:** `Dsdv.h/.cc/.ned`, the bounded history counter in `DsdvTable.h/.cc`, and extensions to `tests/module/DsdvScheduling.test` and `tests/unit/DsdvDissemination.test`. The consumer is the existing periodic callback, not a new MAC-load monitor. Local state and explicit configuration bounds suffice for this first policy.

Configuration rejection is exercised through two additional small module fixtures, `tests/module/DsdvAdaptiveInvalidBounds.test` and `tests/module/DsdvAdaptiveInvalidBudget.test`. They reach actual DSDV initialization with invalid bounds or a zero budget and require the validation diagnostic and exit status. Include them in C3; they are expected initialization-error checks rather than protocol parent regressions.

**Protocol tests to write:** `tests/protocol/dsdv/DsdvAdaptiveDumps.test`. Use one router under test, a deterministic UDP update injector and a silent listening receiver, with jitter zero, small payloads and receiver timeouts derived from the peer-gap bound above. Observe `fullDumpIntervalSelected` and receiver-side decoded fragments; distinguish periodic dumps from overflow dumps by that signal and self-sequence transitions. Measure the first randomized startup phase and calculate subsequent intervals relative to that observed callback rather than assume the first callback occurs at I. In quiet, churn, high-byte-cost and clamp cases, hand-calculate each next interval from C, K and B and assert the timestamps, including the numerical examples above. Inject a withdrawal during a long quiet interval and require delivery before the periodic timer. Force a fragmented overflow dump and prove it does not cancel the next periodic self-sequence advance. Extend `DsdvScheduling` to test restart, which resets I and churn, and minimum/maximum/budget/positive-timeout configuration boundaries.

Add a two-router heterogeneous case to the same protocol file. A uses initial/minimum 2 s, maximum 4 s, neighbor timeout 1.5 s and route timeout 2 s; B uses initial/minimum 0.25 s, maximum 0.5 s and both timeouts 6 s. Both use zero jitter and a 0.1 s settling cap, with a fixture delivery allowance below 0.05 s. Each timeout covers its peer's sending gap, although A's timeout is below A's own sending interval. Require successful initialization, reciprocal host routes and no expiry for 12 s after reciprocal reachability is first established. This directly guards against the unnecessary local-interval validator; it does not claim that arbitrary mismatched peer/timeout configurations are safe.

For the C2-parent comparison, omit the newly introduced adaptive parameter assignments and compare receiver-side periodic packet spacing using the common version-1 header and self-sequence observations. The disabled case must match its C2 parent in scheduling, random draws and filtered DSDV fingerprints, accounting for any intentional C1 changes already present in that parent. The heterogeneous valid-timeout case is added configuration coverage, not a claimed parent failure. A broader static/mobile performance comparison is optional follow-up work, not a completion condition for this bounded policy.

## C4: Base-station default routes

A mobile node two hops from a base station should send an external destination to its DSDV next hop toward that base station. Today the module rejects the extra active uplink and only installs host routes. Merely allowing `0.0.0.0` as another destination would lose the gateway's identity and invite invalid sequence comparisons. Instead, advertise default capability as sequenced metadata attached to the base station's ordinary host route, and derive a local `/0` projection from that route.

### Configuration and external connectivity

Add string parameters `baseStationAddress = ""` on every participant and `externalInterface = ""` on the matching base station. Parse a nonempty base-station value as a valid unicast IPv4 host address. An empty base-station address retains host-only behavior; a matching station with an empty uplink setting simply offers no default capability. Participating nodes must share the configured identity; a capability from another identity is not eligible to supply their default. The base station's configured address is its existing stable ad hoc IPv4 identity.

Permit an extra active non-loopback interface only when it is the base station's explicitly named external interface; other ordinary routers keep the current restriction. Reject an external-interface setting on a non-base-station node, a nonempty interface name that resolves to no interface, reuse of the ad hoc interface as the uplink, or any other extra active interface. Enforce this at initialization and later interface-up notifications. Never send DSDV control on the external interface or import external routes into DSDV. The base station must have IPv4 forwarding enabled and a non-DSDV external default route through that interface. The external network must have a return route for the mobile address range through the base station. Do not add NAT or dynamic external routing.

Declare the capability available only while the uplink is up with carrier and has a usable IPv4 address, IPv4 forwarding is enabled, and IPv4's selected default route is non-DSDV and uses that interface. If the uplink route is absent at startup, participate as an ordinary router with capability false; configuration errors above still fail initialization. Restrict forwarding validation to a single, nonoverlapping ad hoc IPv4 subnet, with its ordinary connected subnet route retained on each participant and a separate wired prefix. The `/32` DSDV routes override that connected route. If an internal host route disappears, the connected route attempts local address resolution; an out-of-range host then fails ARP instead of using the external default. A directly reachable host may still be delivered locally. This prevents default-route fallback from bouncing internal traffic between the base station and its external return route in this fixture. No global ARP, proxy ARP or supplied multihop host routes are permitted in the acceptance fixture.

Reuse `IRoutingTable::getDefaultRoute()` for this profile. The current [Ipv4RoutingTable::internalAddRoute](../../src/inet/networklayer/ipv4/Ipv4RoutingTable.cc) replaces the existing default before inserting a new one; normal insertion does not maintain competing defaults to rank. Do not add another preference calculation or change IPv4 core behavior. Add a module case that replaces the wired default with an ad hoc default and then restores the wired default: capability must become false and then true, with unchanged notifications causing no sequence churn.

Only when `baseStationAddress` is nonempty, subscribe to IPv4 route-added/deleted/changed signals from the referenced routing table and create the reconciliation timer below. Reuse the existing interface notifications for uplink changes. With the gateway profile disabled, leave route subscriptions, reconciliation events and version-2 construction inactive so host-only runs retain their event path and random draws. Dispatch by signal identifier and ignore DSDV's own projection notifications.

[Ipv4RoutingTable::deleteInterfaceRoutes and updateNetmaskRoutes](../../src/inet/networklayer/ipv4/Ipv4RoutingTable.cc) emit route-deleted notifications while iterating their route vector. Default replacement also emits deletion before inserting the new route. Updating DSDV routes synchronously from those callbacks could invalidate an iteration or install a default into that temporary gap, so use one reusable `reconciliationTimer` for C4. When active, coalesce relevant route or uplink notifications into this event at the current simulation time, retaining no borrowed route pointer. Give it priority 5: after ordinary incoming delivery and before existing expiry (10), advertisement (20) and periodic (30) callbacks. The callback reevaluates current external availability and foreign-default suppression, reconciles owned routes, then schedules any resulting urgent advertisements through the existing timer. Own-route notifications never reschedule it. Cancellation on suspend and deletion in the destructor follow the other timer objects; no parallel dirty flag is needed. While inactive, defer no work and reevaluate on start. This extra event boundary permits a packet already scheduled at that time to precede reconciliation; assertions apply after the callback and subsequent advertisement delivery, not inside the routing-table notification.

These checks detect modeled interface/route availability; they do not probe remote Internet reachability. Changing a participant's ad hoc IPv4 identity or configured base-station identity during a run remains unsupported. A wired-address/interface change triggers availability reevaluation without resetting the ad hoc host sequence space.

### State, wire format and propagation

Extend `DsdvEntry` with a default-capability flag and retain both current and advertised values in `RouteEntry` through the existing tuple ownership. Introduce wire version 2 by appending a flags byte to each existing entry: bit 0 is default capability and bits 1–7 must be zero. The header remains 16 bytes; a version-2 entry is 17 bytes, with existing fields in their current order. Version 1 remains exactly 16 bytes per entry and cannot encode true capability. There is no new route for destination `0.0.0.0`: the capability's origin is the existing host destination. The sender header is liveness only, as today; it must not synthesize, refresh or overwrite destination capability when that entry is omitted from a datagram.

Replace the single entry-size constant with version-aware size/capacity helpers shared by construction, serialization and validation. The UDP budget reserves IPv4/UDP overhead exactly as today, then uses `min(UINT16_MAX, floor((budget - 16) / entrySize))` and requires capacity at least one, retaining the existing 16-bit entry-count limit. Reject unknown versions, reserved flags, capability on an infinite route, or capability for an origin other than the configured base station before any route/clock change. Reject serialization of true capability under version 1 instead of silently discarding it. Split structural validation from the receiving domain's expected-version/base-station checks where needed: the serializer can decode either version without consulting module parameters, while `Dsdv` enforces its domain profile before calling `DsdvTable::receive`. Host-only modules send/accept version 1; default-enabled modules send/accept version 2. The standalone serializer supports both. Update equality, printer output and typed dissector behavior where needed; the existing dissector can otherwise continue to visit the extended header without new logic. Update the migration guide to require uniform configuration within a domain.

The base station changes its capability only when computed availability changes: advance its self sequence by two once and make the complete self tuple urgent. Initial start establishes the flag before the startup dump; restart uses the existing even-sequence advance and the freshly computed flag, without a second advance for the same transition. An unchanged availability notification causes neither a sequence advance nor an advertisement. The origin flag is immutable for a given even sequence. Carry it unchanged in every accepted finite route for that origin; an equal-sequence candidate with a conflicting flag is ignored without refreshing that destination, while normal packet-level sender liveness still applies. Do not merge metadata from one sequence with the metric/successor of another.

At receivers, an accepted capability change is urgent in both directions, independent of metric changes and ordinary settling; call the existing urgent-promotion path for the entire accepted tuple. Add capability differences against the full-dump baseline to required incremental selection. If adaptation is enabled, include capability transitions in C3's bounded history, counting an accepted tuple change once even when both its path and capability change. Apply the same once-per-transition rule to local origin capability changes and invalidations. The node's local default uses current forwarding state immediately; its advertisement always uses one complete advertised tuple. This makes a same-metric loss of service propagate through multiple relays without waiting for a periodic full dump. Finite path changes with unchanged capability retain existing settling behavior. Capability withdrawal leaves the finite host route to the base station intact. Actual path failure retains the existing odd/infinite withdrawal and explicitly clears capability on each invalidated non-self entry, including on suspend. An inactive origin sends nothing and recomputes its self flag on restart. A later accepted finite route carries the origin's flag afresh.

Retain destination sequence floors and reuse the existing origin response to an odd self-withdrawal: it chooses a newer even self sequence and retains its currently computed capability. Older capability advertisements cannot reinstall a withdrawn default. No separate gateway sequence counter, election state or gateway route table is needed.

### Forwarding and lifecycle

On a non-base-station node, install at most one DSDV-owned `/0`, using the selected finite route to the configured base station only while its capability is true. Use its successor and hop count. More-specific host routes and the connected ad hoc prefix take precedence through normal IPv4 lookup. If any non-DSDV default exists, preserve it and suppress the DSDV default; reevaluate when that route is added, changed or removed. Such a local conflict is a coexistence case, not evidence that the entire domain can deliver external traffic: the end-to-end acceptance topology has no conflicting mobile defaults. The base station never installs a DSDV default pointing back into the ad hoc domain.

Extend `synchronizeRoutes` to distinguish owned `/32` routes from its owned `/0`. Its current deletion loop indexes every owned route by destination; an unspecified `/0` destination must not be looked up as a DSDV host entry and deleted on every synchronization. Derive the default from the configured origin's current entry and retain no borrowed `IRoute` pointer across callbacks. Apply source ownership checks so foreign defaults, connected routes and the wired default survive reconciliation and lifecycle cleanup.

On accepted capability loss, route expiry or C2 next-hop failure, remove the owned default while synchronizing the current table. Interface loss, stop and crash use the existing removal of all owned routes and cancel reconciliation. A foreign-default or uplink notification takes effect at the deferred reconciliation callback. Preserve unrelated routes and the base station's external default. On restart, revalidate external availability before the startup dump and use the retained sequence state as specified above. An unavailable uplink must not prevent the base station from participating as an ordinary host router.

The single configured base station is a deliberate first boundary: every installed ad hoc default follows the successor chain for the same DSDV destination. Tests must still inspect that chain for loops during loss and recovery. Do not claim multiple-gateway safety or advertise arbitrary prefixes from this design.

A part of a chunk keeps the flags of the chunk

A flag of a chunk says that its content is incomplete, incorrect, or improperly represented, but not where. Thus a part of a flagged chunk now has the flags of the chunk. Before, a part of a BitCountChunk, BitsChunk, ByteCountChunk, or BytesChunk was a clean chunk. For example, the first bytes of an incorrect BytesChunk looked correct. In the same way, a conversion now keeps the incomplete and incorrect flags of the converted data. Before, a typed header that a protocol read from incorrect bytes was correct. The improperly represented flag describes one representation, so the deserializer of the conversion result still decides it. Two chunks with different flags no longer merge into one chunk, because the merged chunk kept only the flags of the first chunk. A packet that got a correct and then an incorrect BytesChunk thus had no bit error. Last, a flagged SequenceChunk now gives its flags to its elements, and a flagged SliceChunk gives its own flags to the parts that a peek or an insertion takes from its source.

Code that reads a part of flagged content must pass the PF_ALLOW_INCOMPLETE, PF_ALLOW_INCORRECT, or PF_ALLOW_IMPROPERLY_REPRESENTED flag, as it already must for a whole flagged chunk. The operations of the packet API that only move data, and the PCAP writers, pass these flags themselves.

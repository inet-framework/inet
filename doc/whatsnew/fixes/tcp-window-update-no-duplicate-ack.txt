A TCP window update is no duplicate ACK

Without SACK, an ACK that repeated the acknowledgment number with another window counted as a duplicate ACK, so three window updates could start a fast retransmit with no segment lost. TCP compared the window of the ACK with the send window after it had already taken that window. RFC 5681 section 2 counts an ACK as a duplicate only when its window equals the window of the last ACK; TcpTahoe, TcpVegas, TcpWestwood and TcpNoCongestionControl did not test the window at all. Now any change of the window makes an ACK no duplicate, as the RFC says. The new parameter duplicateAckWindowRule = "linux" takes only a larger or a zero window, as Linux, so that a smaller window that out-of-order data leaves keeps the duplicate ACK; LinuxTcp sets it.

An 802.1Q tag inserter passes the user priority down

An 802.1Q tag inserter removed the user priority request after encoding it into its tag, so nothing below the inserter got the user priority. In a node that inserts a C-tag and an S-tag (IEEE 802.1ad), the outer tag was sent with PCP 0 instead of the user priority, and an IEEE 802.11 or CSMA/CA interface under an 802.1Q layer sent every frame without it: the 802.11 MAC as a data frame without QoS, the CSMA/CA MAC with best-effort priority.

The user priority belongs to the frame, not to its 802.1Q tag. IEEE Std 802.1Q-2018 carries it as the priority parameter of the service primitives, and a tag only encodes it: "The priority and drop_eligible parameters are encoded in the PCP field of the VLAN tag" (6.9.3). A tagging layer therefore passes the priority of a request down unchanged: the parameters of the request that it makes to the layer below "carry values equal to the corresponding parameters in the received data request" (6.9.2). The inserters now leave the user priority request on the packet. Each tag of a stack takes its PCP from the user priority unless a PCP request of its own tag type sets it, and the MAC below gets the user priority too, so an 802.11 MAC sends a QoS data frame, two bytes longer, in the access category of the user priority.

On receive, nothing changes, as 802.1Q requires. The priority of a tagged frame is "decoded from the tag header" (6.9.1 h), so the PCP of a tag replaces a user priority that the MAC indicated, and in a node that removes two tags the inner tag, which is checked last, sets the user priority, as in a provider edge bridge, whose C-VLAN component decodes the C-tag of a frame that its S-VLAN component passed it with the priority of the S-tag (15.4, 6.14).

The results change for configurations that stack 802.1Q tag inserters in one node, and for configurations with an 802.1Q layer over an 802.11 or CSMA/CA interface whose frames have a user priority request.

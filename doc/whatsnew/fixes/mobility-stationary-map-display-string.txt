A StationaryMobility node stays where it is placed when a map projection is installed

In Qtenv, and in Cmdenv with cmdenv-fake-gui = true, StationaryMobility read its icon position back from the display string in each refreshDisplay(), also when nobody had dragged the icon. GeoMapCanvasVisualizer installs its map projection in INITSTAGE_LAST, after the mobility wrote the icon position through the projection that existed before. The read-back inverted that earlier position through the map projection, so a node placed at Budapest in an Earth-centered, Earth-fixed (ECEF) scene moved to (1.17e6, 1.76e4, -6.25e6) m, off the map. With the default updateFromDisplayString = true, StationaryMobility now takes over the icon position only when its p tag changed since the mobility initialized or last called refreshDisplay(), for example when the user drags the icon. With updateDisplayString = false, a p tag from the Network Description (NED) file or the ini file is no longer taken over at the first refreshDisplay(); initFromDisplayString is the parameter that reads it.

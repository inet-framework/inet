A port that sends a VLAN untagged no longer sends a priority tag

With the default VLAN policy of a bridge, VlanPolicyLayer, a frame of a VLAN that a port sends untagged left that port with a tag of VLAN ID 0 when it carried a PCP request. The direction reverser of a bridge forwards the PCP of a received tag as such a request by default (forwardPcp = true), so every frame that arrived tagged got the priority tag, also a frame of priority 0. A host or a C-VLAN bridge behind such a port that does not expect the tag stopped the run or dropped the frame. VlanReqMapper now removes the VLAN, PCP and drop eligible requests of its tag type when its map sends the VLAN untagged (-1), and requests no tag, as Ieee8021adPolicy does; the priority of the frame stays as its user priority. A configuration that set forwardPcp = false to avoid the fault no longer needs it.

TCP fixes

Many repairs of this release also reach the algorithms and the parameters of INET 4.7, so they change simulations that use LegacyTcp too. In congestion control: a duplicate ACK is counted as RFC 5681 section 2 defines it; ssthresh comes from the FlightSize; each classic flavour answers an ECN-Echo; TcpTahoe answers the third duplicate ACK with slow start; Reno and NewReno with SACK recover as RFC 6675 states, and SACK no longer stops the run for flavours other than TcpReno; slow start grows by the acknowledged bytes, and only while the sender uses the window; NewReno keeps its recovery point after a timeout; and only the first timeout of a segment sets ssthresh. After a timeout, TcpReno, TcpNewReno and DcTcp restart with one full-sized segment of data, as RFC 5681 section 3.1 states; before, a segment of 12 bytes went out with the timestamp option. DCTCP marks its SYN, SYN-ACK and RST with ECT, and counts its bytes also in fast recovery.

The receiver and the sender: the receiver acknowledges at once when a segment fills a gap, and also when the unacknowledged data reach 2*RMSS bytes (RFC 9293 SHLD-19). ECN data carry ECT(0), not ECT(1), and SYN-ACKs, pure ACKs and window probes carry no ECT. A receiver with classic ECN sets ECE in each acknowledging segment of the echo state (RFC 3168 section 6.1.3). PAWS drops a segment with an old TSval, the handshake echoes the timestamps, and each segment after the handshake carries the timestamp option. The MSS option announces the receive limit of the host. The sender avoids silly windows (RFC 9293 MUST-38), and a data segment of the peer updates the send window. The persist timer no longer overwrites the retransmission timer, and the window probe retransmits the first unacknowledged octet. A FIN starts the retransmission timer only when it does not run. A retransmitted SYN gets the SYN-ACK again, and the SYN and the SYN-ACK carry a window of at most 65535 (RFC 7323 section 2.2). Time Exceeded and Parameter Problem errors end a setup.

Nagle's algorithm now holds only new data, as RFC 9293 section 3.7.4 states and as Linux does; before, it held the partial segment of a retransmission until the next timeout. Limited Transmit sends only unsent data (RFC 3042, RFC 6675 step 3.3); before, with SACK and lossDetectionMode = "dupthresh", it retransmitted the first hole. With windowScalingFactor = -1, Tcp selects the smallest shift count that represents the whole window; before, it selected one too small for some windows.

TcpVegas changes cwnd one time for each RTT, as the Vegas paper and Linux do; before, it applied the step at each ACK. TcpVegas and TcpWestwood take initialSsthresh. TcpWestwood takes an RTT sample from each ACK of new data, and sets its threshold from its bandwidth estimate; before, it took no sample, and its window became 4294967295 and then 0. DumbTcp stops its retransmission timer when everything, the FIN included, is acknowledged; before, it sent an acknowledged FIN again every 2 seconds.

Some runs no longer stop. A stopped Tcp drops a segment or an ICMP error that reaches it; before, the run stopped with "Message ... received when Tcp is down". A hard ICMP error in SYN_RCVD informs only an application that has the connection; before, the dispatcher stopped with "Unknown socket". A SEND of zero bytes sends nothing. TcpSpoof declares the checksum of its segments correct, takes the ISS of the clock as Tcp does, and needs a destAddress, which has no default now. Values without a meaning stop the run at the start with an error that names the parameter: an mss below 88 other than -1, a dupthresh or an initialSsthresh below 1, a gain g of DcTcp outside (0, 1], and a negative delayedAckTimeout, keepAliveIdleTime or keepAliveInterval.

These repairs move fingerprints and statistical results of the INET examples, for example 27 fingerprints for the Nagle repair and 30 fingerprints for the repairs of the parameters.

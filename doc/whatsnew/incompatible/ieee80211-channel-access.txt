IEEE 802.11 channel access: TXOP protection, NAV, recovery and QoS DATA lifetime

With single protection, the default of the new TxopProcedure parameter protectionMechanism, HCF now checks the complete cost of a continuation when Block Ack support is off. Before the next SIFS, the cost of the exchange must be less than the remaining TXNAV, and the initial SIFS and the exchange must fit in a positive TXOP limit. A refused frame waits for a new grant, without a retry increment or failed-rate feedback. A continuation that needs RTS/CTS is refused before the RTS, but an initial exchange can still use RTS/CTS. Rx keeps the shared TXNAV apart from the received NAV, and TXNAV blocks contention also after the end of the TXOP. TxopProcedure::getRemaining() now gives the remaining time of the TXOP; before, it gave the elapsed time, so the admission checks of HCF compared with the wrong value.

The new value protectionMechanism = "multiple" selects multiple protection for EDCA TXOPs. For example, a PPDU of 200 us in a TXOP of 1024 us advertises a reservation of 824 us. Multiple protection uses the shared TXNAV, and it does not check a complete exchange against the remaining budget. The IEEE 802.11 chapter of the User's Guide explains the timing and the limits.

CTS, ACK and Basic Block Ack responses keep their Duration fields, but they no longer extend the local NAV of the recipient. So a recipient can answer another RTS of the same holder. HCF clamps response durations to zero, and rounds them up to whole microseconds. Rx gives local evidence of the interframe space on accepted frames. A radio command now waits until Tx completes an accepted transmission, including the SIFS before a response.

A management failure now changes the contention window and the retry state of its own access category; before, it changed the best-effort window, also for voice management frames. The hcf.edca.mgmtAndNonQoSRecoveryProcedure module therefore moves below each edcaf[i], and its C++ getter moves from Edca to Edcaf: update the configuration, the signal subscriptions and the result paths. QoS recovery keeps separate retry counters for each receiver. An access category without a frame no longer takes part in an internal collision, so expired voice DATA no longer makes valid video DATA lose. Two crashes in the retry accounting of management frames and in the grant callback of Contention are corrected.

HCF now discards QoS DATA when its finite lifetime expires, with Block Ack support on or off. Each access category has the new parameter mac.hcf.edca.edcaf[*].msduLifetime, 0.512 s by default, which starts when the MAC accepts the frame, so DATA can expire in the queue. HCF records these drops as packetDropLifetimeExpired. Congested QoS simulations can therefore send newer DATA, for example the Block Ack fragmentation showcase, the QoS showcase and the MacQos examples.

These changes can change the results and the fingerprints of IEEE 802.11 simulations. They require the modification of C++ code that implements MAC parts outside INET: ITx has the new method hasTransmission(), and both transmitFrame() overloads take an explicit updateLocalNav; IRx has invalidateInterframeHistory() and the TXNAV operations; frame sequence callbacks get a start notification and a Boolean submission result; a custom radio must give local endpoint and completion indications; a custom ACK policy must not depend on the second policy query of HCF, which is removed. See the migration guide.

IEEE 802.11 Block Ack: immediate Compressed Block Ack, and a repaired agreement lifecycle

HCF now uses immediate Compressed Block Ack by default. Eligible HT infrastructure links and the supported ac path set up agreements and answer with Compressed Block Ack frames of 32 bytes with the FCS. Links without usable local or peer HT state keep Normal Ack; an HT PHY mode alone does not give the HT state of the peer. The new Hcf parameter blockAckVariant selects the variant: "compressed" (the default), or "basic" for the Basic Block Ack of IEEE Std 802.11e-2005, whose type value IEEE Std 802.11-2024 reserves. Both endpoints must select the same variant, because ADDBA does not negotiate it: a valid BAR of the other variant stops the simulation with a message that names the peer, the TID and the variants. HCF refuses an unknown value at initialization, also when Block Ack support is off, and Compressed refuses delayedAckPolicySupported = true. The existing Block Ack, TXOP, QoS and fragmentation demonstrations select "basic", so their configurations and results stay.

With Compressed Block Ack, the receipt state keeps its positive bits after delivery. The reorder service releases frames across a receive gap only with local evidence of the interval (SIFS or a permitted RIFS) from Rx, so a valid frame can wait behind missing sequence numbers until a later BAR or another recovery. Fragmentation is off for the peer and TID of a Compressed agreement. A Compressed BAR uses a legal non-HT rate from the rate sets of the BSS and of the peer, so a configured controlFrameBitrate must obey that rule, and the durations, the protection and the timeouts use the response length of 32 bytes (Basic: 152 bytes). Before HCF aggregates DATA destructively, it checks that the complete exchange fits; if an aggregate cannot fit, HCF tries its first ordinary MSDU with the same mode, and a refusal keeps the queued frames, their deadlines and the sequence state. Basic, and traffic outside active Compressed agreements, keep their admission limits. A failed RTS before the DATA commitment changes the retry state of the access category without a provisional sequence counter, the original DATA lifetimes limit the attempts, and a QSRC rollover does not discard the queued DATA. Multi-TID Block Ack, the delayed Basic variant, the A-MPDU requirements of n and ac, complete VHT transfers and MAC stop and start recovery are not modeled yet.

The agreement lifecycle follows the standard more closely. HCF processes an accepted Block Ack Action once, after the duplicate checks, and the setup matches the peer, the TID and the dialog token. The response of the recipient decides the buffer size, the inactivity timeout and the use of A-MSDU. HCF holds new DATA back during setup and recovery. The wait for the response starts after the ACK of the request (addbaFailureTimeout, 100 ms by default), and an uncertain setup needs a DELBA before the held DATA continues; a failed DELBA discards the held batch, and later DATA can start a new recovery. The first DATA under an accepted agreement keeps the sequence number of the request. Lifetime expiry, an RTS failure and an internal collision that discards the first DATA end the agreement. A teardown in one direction keeps the agreement of the other direction, and the originator discards the transmitted and unacknowledged DATA and the unsent fragments of the units that the agreement started; later intact DATA stays eligible, also across a wraparound of the sequence numbers. After the final DATA, the originator sends a DELBA also with a zero inactivity timeout, so a later burst can need a new ADDBA exchange. Basic BAR selection is separate for each peer and TID, so short bursts and small windows can cause a BAR below the configured threshold, and a BAR can get channel access without queued DATA. With Basic Block Ack, single protection reserves only a successor that is already prepared: more DATA starts a new TXOP and can need more contention, and the final DATA of a TXOP with a zero limit reserves only its immediate response. A retransmitted standalone QoS DATA after lost or negative Block Ack feedback has the Retry bit and keeps its sequence number and TID, which changes the FCS in the packet data fingerprints but not the lengths or the schedule.

The recipient delivers in order. A Basic Block Ack recipient counts sequence positions as buffer capacity, and all fragments of one MSDU take one position. DATA that fills a gap releases all following complete units at once, DATA beyond the window moves the window, and a valid BAR creates and moves an empty reorder record. Delivery follows the cyclic order of the sequence numbers, also 4095 before 0. An association reset discards the old buffered units in both directions, and the queued and in-progress QoS DATA for the old peer, also unsent Normal Ack DATA.

The serializer supports the complete Type field of 4 bits for Basic and Compressed frames. A Compressed response has a bitmap of 64 bits, and both BAR variants have 24 bytes with the FCS. A Basic producer must keep the reserved bits that overlap Type zero. Invalid Types and invalid fragment fields fail validation. MPDU deaggregation stops at an invalid or too long delimiter, before it reads past the end of the data.

These changes alter the order of the exchanges, airtime, delivery, contention, simulation results and fingerprints of Block Ack configurations. They require the modification of C++ code that implements Block Ack parts outside INET: agreement handlers, recipient services, management, QoS ACK policies (isBlockAckReqNeeded() and computeBlockAckReqParameters() take the agreement handler, and the callers of BAR selection and of the processing of a transmitted BAR must give the agreement arguments, or the code does not compile), in-progress queues (getPendingFrameFor() keeps its extract argument), rate selectors, frame sequences and IRx. QoS data services implement IOriginatorQosMacDataService, which gives a DATA preview before extraction: a commit transfers the preview, and a refused commit keeps the preview and the queue. A commit of ordinary DATA keeps the effects of a normal queue service, so the queue statistics count the departure. An external queue needs the optional contract of selected extraction only when held DATA hides eligible work. BlockAckReordering returns the ordered ReleasedFrames, and delivery code must keep that order through reassembly and deaggregation. The protected getEarliestCompleteMsduOrAMsduIfExists() stays for one release, but it is deprecated. See the migration guide.

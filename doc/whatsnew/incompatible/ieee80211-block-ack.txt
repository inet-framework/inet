IEEE 802.11 Block Ack: immediate Compressed Block Ack, and a repaired agreement lifecycle

HCF now uses immediate Compressed Block Ack by default. Eligible HT infrastructure links and the supported ac path set up agreements and answer with Compressed Block Ack frames of 32 bytes with the FCS; a link keeps Normal Ack when the local or the peer HT state is not usable. The new Hcf parameter blockAckVariant selects "compressed" (the default) or "basic", the Basic Block Ack of IEEE Std 802.11e-2005. Both endpoints must select the same variant, because ADDBA does not negotiate it: a BAR of the other variant stops the simulation with a message that names the peer, the TID and the variants. The existing Block Ack, TXOP, QoS and fragmentation demonstrations select "basic", so their configurations and results stay.

With a Compressed agreement, fragmentation is off for its peer and TID, a BAR uses a legal non-HT rate (so a configured controlFrameBitrate must be one), and HCF aggregates DATA only when the complete exchange fits. A received frame can wait behind missing sequence numbers until a later BAR or another recovery. Multi-TID Block Ack, the delayed Basic variant, the A-MPDU requirements of n and ac, complete VHT transfers and MAC stop and start recovery are not modeled yet.

The agreement lifecycle follows IEEE Std 802.11-2024 more closely. The setup matches the peer, the TID and the dialog token, and the response of the recipient decides the buffer size, the inactivity timeout and the use of A-MSDU. HCF holds new DATA back during setup and recovery, and the wait for the response starts after the ACK of the request (addbaFailureTimeout, 100 ms by default). Lifetime expiry, an RTS failure or an internal collision of the first DATA ends an agreement, and after the final DATA the originator sends a DELBA, so a later burst can need a new ADDBA exchange. Basic BAR selection is separate for each peer and TID, so a BAR can come below the configured threshold. A retransmitted QoS DATA after failed Block Ack feedback has the Retry bit.

The recipient delivers complete units in the cyclic order of the sequence numbers, across gaps and window moves, and a Basic recipient counts all fragments of one MSDU as one buffer position. An association reset discards the old buffered units and the QoS DATA for the old peer. The serializer supports the complete Type field of 4 bits, both BAR variants have 24 bytes with the FCS, a Basic producer must keep the reserved bits that overlap Type zero, and MPDU deaggregation stops at an invalid delimiter.

These changes alter the exchanges, airtime, delivery, results and fingerprints of Block Ack configurations. C++ code that implements Block Ack parts outside INET must change: agreement handlers, recipient services, management, QoS ACK policies (isBlockAckReqNeeded() and computeBlockAckReqParameters() take the agreement handler), in-progress queues (getPendingFrameFor()), QoS data services (IOriginatorQosMacDataService gives a DATA preview before extraction), rate selectors, frame sequences and IRx. BlockAckReordering returns the ordered ReleasedFrames, and the protected getEarliestCompleteMsduOrAMsduIfExists() is deprecated and stays for one release. The IEEE 802.11 Block Ack sections of the migration guide give the details.

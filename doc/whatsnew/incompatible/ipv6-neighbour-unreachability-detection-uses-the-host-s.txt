IPv6 Neighbour Unreachability Detection uses the host's ReachableTime

A Neighbour Cache entry stayed REACHABLE for exactly 30 s after a
reachability confirmation. The baseReachableTime parameter of
Ipv6NeighbourDiscovery, the HostBaseReachableTime attribute of the routing
table configuration and the Reachable Time field of a received Router
Advertisement were stored, but Neighbour Unreachability Detection did not
read them. It now uses ReachableTime, a random value between 0.5 and 1.5
times BaseReachableTime, as RFC 4861 Sections 6.3.2 and 7.3.3 require. The
parameter also keeps fractions of a second now: a value such as 0.5s was
truncated to 0.

An INET router advertises its advReachableTime parameter, 3600s by default,
so a host that receives its Router Advertisements now keeps an entry
REACHABLE for 1800 to 5400 s instead of 30 s. The results of IPv6
simulations in which a neighbour is used again after a pause change.

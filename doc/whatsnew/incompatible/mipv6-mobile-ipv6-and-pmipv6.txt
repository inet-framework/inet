Mobile IPv6 and Proxy Mobile IPv6 corrections

A first home registration of Mobile IPv6 now sends one Binding Update. InitialBindackTimeoutFirstReg is 1.5 s, the value of RFC 6275; before, it was 1 s, the time of the Duplicate Address Detection of the home agent, so the Binding Acknowledgement always came too late and each first registration sent a second Binding Update. Mipv6 now also applies the first-registration timeout to home registrations; before, that branch could not run. The fingerprints of examples/ipv6/mipv6 and of the mipv6roaming example change.

MobilityHeaderSerializer writes and reads the Proxy Registration (P) flag of a Binding Acknowledgement at 0x20, as RFC 5213 section 10 assigns it; before, it used 0x40, the Mobile Router (R) flag of RFC 3963, so a received Binding Acknowledgement with the R flag was read as a proxy one. A Mobile Access Gateway now sends Handoff Indicator 4 (handoff state unknown) in its Proxy Binding Updates, as RFC 5213 section 6.9.1.1 requires when it learns of an attachment from the access link only; before, it sent 1. The Local Mobility Anchor does not read the indicator, so simulations behave as before, but the bytes of these messages change.

An IPv6 node that decapsulated an IPv6-in-IPv6 datagram crashed when a netfilter PREROUTING hook dropped the inner datagram, because the datagram was deleted twice. A Mobile IPv6 home agent drops a tunneled datagram from a source without a binding, so such a home agent crashed at the first one. The datagram is now dropped and the simulation continues.

In examples/ipv6/pmipv6, the mobile node is a plain host without mobility software, as PMIPv6 intends, and the network parameters can be changed from the ini file.

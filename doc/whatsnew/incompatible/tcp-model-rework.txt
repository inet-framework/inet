TCP model rework: the defaults of the RFCs, LinuxTcp and LegacyTcp

The TCP model was reworked. A flavour is now a choice of congestion control (ITcpCongestionControl) and of loss recovery (ITcpRecovery). The model gained CUBIC (TcpCubic), RACK-TLP loss detection, Proportional Rate Reduction, F-RTO, the undo of a spurious loss, Accurate ECN, TCP Fast Open, keepalive probes, the path MTU search of RFC 4821, and many parameters that select a behavior of Linux. The documentation of the Tcp module lists each RFC, what the model implements, and where it departs from the RFC.

The defaults of Tcp now follow the RFCs. This changes each simulation that uses TCP without setting these parameters (INET 4.7 -> now):

  sackSupport              false             -> true
  timestampSupport         false             -> true
  windowScalingSupport     false             -> true
  delayedAcksEnabled       false             -> true
  limitedTransmitEnabled   false             -> true
  advertisedWindow         14 * this.mss     -> 65535
  mss                      536               -> -1 (1460 for IPv4, 1440 for IPv6)
  initial window           one segment       -> initialWindow = "rfc3390" (RFC 5681 section 3.1)
  tcpAlgorithmClass        "TcpReno"         -> "TcpNewReno"
  initial RTO              3 s               -> initialRto = 1s
  loss detection           three duplicates  -> RACK-TLP (lossDetectionMode, tlpEnabled)
  recovery window          halved at once    -> PRR (prrEnabled)
  PSH                      never set         -> on the last buffered segment (pushLastBufferedSegment)
  ECN                      off               -> answers a request (tcpEcnMode = "passive")
  pmtudEnabled             false             -> true (DF on IPv4 segments)

The results of TCP simulations differ from INET 4.7 in any case, also because many defects were repaired (see the TCP bug fixes). To keep the old defaults, select LegacyTcp, which extends Tcp and changes only defaults:

  **.tcp.typename = "LegacyTcp"

LinuxTcp extends Tcp in the same way, with the defaults of Linux 7.1: CUBIC with the hybrid slow start, an initial window of ten segments, the timers and the delayed ACK of Linux, a receive buffer of 131072 bytes (receiveBufferSize, the tcp_rmem[1] of Linux), and the other behaviors of Linux that parameters select. Tcp keeps no receive buffer apart from the window. A parameter that the ini file sets takes precedence over the defaults of the selected module.

Some behaviors follow Linux on request. With windowAutoTuning and a receive buffer, a receiver grows its buffer in a long transfer by Dynamic Right-Sizing, up to the new parameter receiveBufferMax (32 MiB, the tcp_rmem[2] of Linux); receiveBufferLowRtt (1 ms) selects a smaller growth for small RTTs, and the status of a connection reports the receive RTT and the receive space (rcvRtt and rcvSpace of TcpStatusInfo). In the autoRead mode, each delivery to the application is a read. The automatic window scale (windowScalingFactor = -1) then also covers receiveBufferMax, as Linux does: with the default of 32 MiB, the shift is 10. Before, a buffer of 131072 bytes got a shift of 1, and the offered window could not grow above 131070 bytes. A buffer that SO_RCVBUF locks keeps the shift of its own window. Simulations with LinuxTcp, and simulations that turn windowAutoTuning on with a receive buffer, change. The new parameter dropSynData drops the data of a SYN without Fast Open, as Linux does; LinuxTcp sets it, and Tcp keeps the data, as RFC 9293 section 3.10.7.2 allows; the data of a SYN with an invalid Fast Open cookie is dropped in both modes, as before. Simulations with LinuxTcp in which a client sends data on a SYN without Fast Open change. The new parameter urgentOutOfBand, which LinuxTcp sets, takes the last byte of urgent data out of the stream, and a read stops before it, as Linux does without SO_OOBINLINE; INET does not deliver that byte, and it sends no urgent data. Tcp keeps the URG-marked bytes as ordinary data, so simulations change only where a peer sends urgent data to LinuxTcp.

The first round-trip measurement now sets SRTT = R and RTTVAR = R/2, as RFC 6298 section 2.2 states. Before, the estimator folded it into the recurrence from srtt = 0, so the first timeout described the initial guess and not the path. A new rttMeasured flag of the algorithm state tells the two cases apart. The early retransmission timeout of each TCP connection changes.

TcpSocket has new per-connection options and per-write flags of the Linux socket API: setNoDelay() (TCP_NODELAY), setCork() and the more flag of send() (TCP_CORK, MSG_MORE), the eor flag of send() (MSG_EOR), setMaxSeg() (TCP_MAXSEG), setNotsentLowat() (TCP_NOTSENT_LOWAT, also the module parameter notsentLowat), sendZerocopy() with the callback socketZerocopyCompletion() (MSG_ZEROCOPY), setTimestamping() (SO_TIMESTAMPING), setReceiveBufferSize() (SO_RCVBUF), setSynRetries() (TCP_SYNCNT), setKeepAlive(), and connect() with Fast Open. The STATUS reply (TcpStatusInfo) fills the fields of TCP_INFO of Linux. The TCP header has the Fast Open and Accurate ECN options. The connection has the new signals sndMax, delivered and deliveredCe, and Tcp emits packetSentToLower for each segment, as Udp does.

Two parameters are deprecated: increasedIWEnabled (use initialWindow = "rfc3390") and ecnWillingness (use tcpEcnMode = "rfc3168"). They still work in this release. Two C++ base classes were renamed: TcpBaseAlg is now TcpAlgorithmBase, and TcpTahoeRenoFamily is now TcpClassicAlgorithmBase; the old names remain as deprecated aliases in this release. A TCP algorithm outside INET needs more than the rename: the split into congestion control and recovery moved much of the protected interface that a flavour overrides, so such an algorithm must be written against ITcpCongestionControl and ITcpRecovery.

TCP model rework: the defaults of the RFCs, LinuxTcp and LegacyTcp

The TCP model was reworked. A flavour is now a choice of congestion control (ITcpCongestionControl) and of loss recovery (ITcpRecovery). The model gained CUBIC (TcpCubic), RACK-TLP loss detection, Proportional Rate Reduction, F-RTO, the undo of a spurious loss, Accurate ECN, TCP Fast Open, keepalive probes, the path MTU search of RFC 4821, and many parameters that select a behavior of Linux. The documentation of the Tcp module lists each RFC, what the model implements, and where it departs from the RFC.

The defaults of Tcp now follow the RFCs. This changes each simulation that uses TCP without setting these parameters (INET 4.7 -> now):

  sackSupport              false             -> true
  timestampSupport         false             -> true
  windowScalingSupport     false             -> true
  delayedAcksEnabled       false             -> true
  limitedTransmitEnabled   false             -> true
  advertisedWindow         14 * this.mss     -> 65535
  mss                      536               -> -1 (1460 for IPv4, 1440 for IPv6)
  initial window           one segment       -> initialWindow = "rfc3390" (RFC 5681 section 3.1)
  tcpAlgorithmClass        "TcpReno"         -> "TcpNewReno"
  initial RTO              3 s               -> initialRto = 1s
  loss detection           three duplicates  -> RACK-TLP (lossDetectionMode, tlpEnabled)
  recovery window          halved at once    -> PRR (prrEnabled)
  PSH                      never set         -> on the last buffered segment (pushLastBufferedSegment)
  ECN                      off               -> answers a request (tcpEcnMode = "passive")
  pmtudEnabled             false             -> true (DF on IPv4 segments)

The results of TCP simulations differ from INET 4.7 in any case, also because many defects were repaired (see the TCP fixes). LegacyTcp extends Tcp and changes only the defaults, back to those of INET 4.7:

  **.tcp.typename = "LegacyTcp"

LinuxTcp extends Tcp in the same way, with the defaults of Linux 7.1: CUBIC with the hybrid slow start, an initial window of ten segments, the timers and the delayed ACK of Linux, a receive buffer of 131072 bytes, and the behaviors of Linux that parameters select. These include Dynamic Right-Sizing of the receive buffer with windowAutoTuning up to receiveBufferMax (32 MiB), a window scale that covers receiveBufferMax, dropSynData (drop the data of a SYN without Fast Open) and urgentOutOfBand (take the last byte of urgent data out of the stream). Tcp has no receive buffer apart from the window, keeps the data of a SYN, and treats urgent bytes as ordinary data. A parameter that the ini file sets takes precedence over the defaults of the selected module.

The first round-trip measurement now sets SRTT = R and RTTVAR = R/2, as RFC 6298 section 2.2 states, so the early retransmission timeout of each TCP connection changes.

TcpSocket has new options and flags of the Linux socket API, for example setNoDelay(), setCork(), setMaxSeg(), setNotsentLowat(), sendZerocopy(), setTimestamping(), setReceiveBufferSize(), setSynRetries(), the eor flag of send() and connect() with Fast Open, and its STATUS reply fills the fields of TCP_INFO. The connection has the new signals sndMax, delivered and deliveredCe, and Tcp emits packetSentToLower.

The parameters increasedIWEnabled (use initialWindow = "rfc3390") and ecnWillingness (use tcpEcnMode = "rfc3168") are deprecated, and they still work in this release. TcpBaseAlg is now TcpAlgorithmBase, and TcpTahoeRenoFamily is now TcpClassicAlgorithmBase; the old names stay as deprecated aliases in this release. A TCP algorithm outside INET needs more than the rename: it must be written against ITcpCongestionControl and ITcpRecovery, because the split moved much of the protected interface that a flavour overrides.

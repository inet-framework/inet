IEEE 802.1ad: S-tags and C-tags together, port-based VLAN policy, and the PCP of the tag inserters

A node can now carry an S-tag (IEEE 802.1ad) and a C-tag at the same time, so it can insert or remove both tags, as a provider edge bridge does. The request and indication tags of the C-tag therefore have new names, and the S-tag has tags of its own (SVlanReq, SPcpReq, SDropEligibleReq and their indications). There are no aliases: code that uses these tags, and a classifierClass parameter that names an old classifier function, must use the new names:

  VlanReq, VlanInd                    -> CVlanReq, CVlanInd
  PcpReq, PcpInd                      -> CPcpReq, CPcpInd
  DropEligibleReq, DropEligibleInd    -> CDropEligibleReq, CDropEligibleInd
  inet::PacketVlanReqClassifier       -> inet::PacketCVlanReqClassifier
  inet::PacketVlanIndClassifier       -> inet::PacketCVlanIndClassifier

The modules that use the VLAN tags, for example the VLAN policy modules, the relays, the PCP classifiers, the stream coders and the packet taggers, have the new parameter vlanTagType, "c" by default, and the layers pass it to their submodules. So one line makes a node an S-VLAN bridge: *.switch.**.vlanTagType = "s". An S-VLAN node must set it on all of these modules: a node that sets it only on the 802.1Q layer, which was enough before, runs without VLAN separation or stops with an error that does not name the cause. The protocol parameter of VlanReqMapper is replaced by vlanTagType; delete the lines that set it.

An 802.1Q tag inserter now takes the PCP of its tag from a PCP request of its tag type, from the user priority request (mapUserPriorityReqToPcpReq), or from defaultPcp, and it indicates that PCP as the user priority of the frame (mapPcpIndToUserPriorityInd). It leaves the user priority request on the packet for the layers below, as IEEE Std 802.1Q-2018 6.9.2 requires, unless removeUserPriorityReq is true. Before, defaultPcp overrode an explicit user priority request. A value outside [0, 7] is an error now. The defaultUserPriority parameter is removed:

  **.qTagHeaderInserter.defaultUserPriority = 5  ->  **.qTagHeaderInserter.defaultPcp = 5

The lookup and update methods of IMacForwardingTable, MacForwardingTable and MrpMacForwardingTable no longer have a default VLAN ID of 0. Code outside INET that calls them without a VLAN ID does not compile: give the VLAN of the frame, or 0 if the caller does not know VLANs.

The new VLAN policy Ieee8021adPolicy, for the vlanPolicy submodule of BridgingLayer, configures each port of a bridge by its IEEE 802.1Q port type ("access", "trunk", "cnp" or "pnp") and its VLAN ids, in place of the four maps for each port of VlanPolicyLayer, and it follows the rules of the standard for these ports:

  *.switch.bridging.vlanPolicy.typename = "Ieee8021adPolicy"
  *.switch.bridging.vlanPolicy.ports = {"eth0" : {"type" : "access", "vid" : 10}, "eth1" : {"type" : "trunk", "vids" : [10, 20]}}

VlanPolicyLayer stays for VLAN id translation and other configurations, and its new VlanIndMapper can put the untagged ports of one bridge into different VLANs. The new example examples/ethernet/providerbridging and the new showcase showcases/ethernet/sharedcore show provider bridging. See the migration guide.

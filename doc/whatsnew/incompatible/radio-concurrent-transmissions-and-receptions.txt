Radio: concurrent transmissions and receptions

Radio can now transmit any number of signals at the same time, and attempt any number of receptions at the same time, as a technology with concurrent per-user transmissions (e.g. a cellular base station) needs. Both are allowed by new Radio parameters, allowConcurrentTransmissions and allowConcurrentReceptions, which default to false. With allowConcurrentReceptions set, every reception the receiver's computeIsReceptionAttempted() accepts is attempted alongside the ones in progress; the receivers shipped with INET attempt one reception at a time either way, so the switch only matters with a receiver that attempts more.

The behavior with the defaults is unchanged, but the C++ API of Radio subclasses changed: the protected receptionTimer and transmissionTimer members were replaced by the attemptedReceptionTimers and transmissionTimers vectors, and continueTransmission(), endTransmission() and abortTransmission() take the transmission timer as an argument. A subclass that dropped the attempted reception on a reconfiguration by resetting receptionTimer calls abandonAttemptedReceptions() instead. getTransmissionInProgress(), getReceptionInProgress(), getTransmittedSignalPart() and getReceivedSignalPart() answer as before while at most one signal is in progress in their direction, and throw an error while several are. A model that relies on them, such as the StateBasedEpEnergyConsumer and StateBasedCcEnergyConsumer energy consumers, therefore cannot be used with a radio that has several signals in progress at once.

This change requires the modification of C++ code that derives from Radio and accesses these members or overrides these methods.

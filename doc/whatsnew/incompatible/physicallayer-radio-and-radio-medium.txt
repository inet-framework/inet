Radio and radio medium: concurrent signals, the path loss of a reception, and the SNIR of an interval

Radio can now transmit any number of signals at the same time, and attempt any number of receptions at the same time, as a technology with concurrent transmissions for each user needs (for example a cellular base station). The new Radio parameters allowConcurrentTransmissions and allowConcurrentReceptions, false by default, turn this on. The receivers of INET attempt one reception at a time, so the receptions switch matters only with a receiver that attempts more. IRadio has the new methods getTransmissionsInProgress() and getReceptionsInProgress(), which ReceiverBase and the canvas visualizers use; for Radio, NoiseSource and ShortcutRadio, they hold at most one element. getTransmissionInProgress(), getReceptionInProgress(), getTransmittedSignalPart() and getReceivedSignalPart() answer as before while at most one signal is in progress in their direction, and they throw an error while several are; so StateBasedEpEnergyConsumer and StateBasedCcEnergyConsumer cannot be used with a radio that has several signals in progress.

A path loss now computes the loss of one reception and knows its receiver. IPathLoss::computePathLoss(transmission, arrival) is replaced by computeReceptionPathLoss(receiverRadio, transmission, arrival), which returns an IReceptionPathLoss that gives the loss factor at any frequency. ScalarMediumAnalogModel evaluates it at the center frequency, and DimensionalMediumAnalogModel across the band. With the receiver, a path loss can keep state for each link, for example a shadowing that is correlated over distance. The form that takes only a distance, computePathLoss(propagationSpeed, frequency, distance), is renamed to computeDistancePathLoss(); it can be NaN when the distance alone does not give the loss (TwoRayInterference). The PathLossBase default of the new method evaluates it, so the results of models that implement only that form do not change. TwoRayGroundReflection and TwoRayInterference now use the geometry of the link under DimensionalMediumAnalogModel too.

LogNormalShadowing has the new parameter correlationDistance. With the default (NaN), each reception draws a new shadowing value. With a distance, the value is kept for each pair of radios, the same in both directions, and drawn again only when a radio has moved farther than that distance; the values of a radio are dropped when the radio leaves the medium. Without a correlation distance, LogNormalShadowing now draws one value for each reception also with DimensionalMediumAnalogModel; before, the frequencies of one reception had independent values. With ScalarMediumAnalogModel, or with the default attenuation at the center frequency, nothing changes.

ISnir has three new pure virtual functions, getMin(), getMax() and getMean() of a time interval, so a model of a part of the signal can use the SNIR of that part. ScalarSnir, DimensionalSnir and UnitDiskSnir implement them, and the values for the whole reception do not change. SnirReceiverBase has a new overload of computeIsReceptionSuccessful() for a time interval, and the function without the interval calls it with the limits of the reception. IRadioMedium has computeInterference(receiver, listening), formerly a protected member of RadioMedium, so a radio can compute a hypothetical SNIR from the public API. The result is not cached, and the receptions that the medium did not compute yet are computed at the call, with their random numbers. RadioMedium has the new parameter transmissionPurgeMode: "timer", the default, removes old transmissions with a self-message as before, and "onTransmission" removes them when a new transmission is added, so the medium schedules no events of its own, and its bookkeeping does not change fingerprints. The interference is the same in both modes.

This change requires the modification of C++ code that implements or calls computePathLoss(), constructs FrequencyDependentAttenuationFunction objects (the reception path loss is now its second argument), implements IRadio, ISnir or IRadioMedium without the INET base classes, or derives from Radio and uses its timers: receptionTimer and transmissionTimer are now the vectors attemptedReceptionTimers and transmissionTimers, continueTransmission(), endTransmission() and abortTransmission() take the transmission timer, and abandonAttemptedReceptions() replaces a reset of receptionTimer. A subclass that calls or overrides RadioMedium::removeNonInterferingTransmissions() must call scheduleRemoveNonInterferingTransmissionsTimer() itself. See the migration guide for the SNIR.

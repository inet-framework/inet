IPv6 Neighbor Discovery corrections

A datagram whose transport gives no hop limit now leaves with the CurHopLimit of its outgoing interface (RFC 4861 section 6.3.2): 64 by default, or the Cur Hop Limit of the last Router Advertisement on that interface. Before, every such datagram left with the constant 30, and the value of the router was stored but not used. The hop limit field of most IPv6 datagrams changes, so the fingerprints that include packet data change.

Two defaults of Ipv6RoutingTable follow RFC 4861 section 6.2.1: advCurHopLimit is 64 (it was 30), and advLinkMtu is 0 (it was 1280). A Router Advertisement now carries an MTU option only when advLinkMtu is not 0; before, it always carried one, also with the value 0. Set advLinkMtu to keep the MTU option. Every Router Advertisement with the defaults is 8 octets shorter, so simulations with routers of IPv6 change.

A host now sends datagrams of at most the LinkMTU of an interface, which an MTU option of a Router Advertisement sets (RFC 4861 section 6.3.4). Before, the host stored the value and fragmented to the MTU of the interface. The default of LinkMTU is now the MTU of the interface (it was 1280), and a host takes an MTU option only between 1280 and the MTU of the interface.

Address resolution and the probes of Neighbor Unreachability Detection now wait the RetransTimer of the interface between two solicitations, which a Router Advertisement sets (RFC 4861 section 6.3.4). Before, they waited the constant RETRANS_TIMER, and Duplicate Address Detection read the Retrans Timer field, in milliseconds, as seconds. The default of AdvRetransTimer is now 0 (it was 1, in a field of milliseconds), as RFC 4861 section 6.2.1 states, so a router with the default leaves the Retrans Timer field unspecified.

A router now answers every Router Solicitation, within the rate limit of RFC 4861 section 6.2.6. Before, it answered only the first one until its first periodic advertisement, 198 to 600 seconds after the start, because the time of its next advertisement stayed at the time of the first answer.

The first three Router Advertisements of an interface now come at most MAX_INITIAL_RTR_ADVERT_INTERVAL, 16 seconds, apart (RFC 4861 section 6.2.4), and a multicast answer to a solicitation restarts the advertising timer as if an unsolicited advertisement had been sent (section 6.2.6). Before, the first periodic advertisement came 198 to 600 seconds after the start, the cap applied from the second to the fourth one, and an answer did not touch the timer. The advertising timer of a router starts when the router has booted (routerBootupTime), so that routers that start together do not advertise in step. Simulations with routers of IPv6 now see their first advertisements in the first seconds.

A TCP connection setup lasts as long as its SYN retransmissions

An active open of Tcp no longer fails after 75 s, and a passive open no longer leaves SYN_RCVD after 75 s. The SYN and SYN-ACK retransmissions alone limit the setup (the synRetries parameter, or TcpSocket::setSynRetries() for one connection), as in Linux. With the defaults of Tcp, 12 retransmissions take about 24 minutes; RFC 9293 section 3.8.3 asks for at least 3 minutes (MUST-23). LinuxTcp keeps the 11 s of Linux. Simulations in which a SYN or a SYN-ACK gets no answer for more than 75 s change.

When the retransmissions run out, the setup now times out: an active open tells the application with TCP_I_TIMED_OUT, as connect() of Linux fails with ETIMEDOUT, and a passive open returns to LISTEN, or closes if it was forked. Before, the connection aborted without an indication to the application, and a listener that does not fork closed.

The timer that waits for the SEND of a deferred Fast Open SYN is now TcpConnection::deferredSynTimer, with the constant TCP_TIMEOUT_DEFERRED_SYN. See the migration guide.

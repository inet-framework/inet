Ethernet: the CSMA/CD attempt limit, frames without an FCS, and EtherTypes that INET does not know

The half-duplex Ethernet MAC modules EthernetCsmaMac and EthernetCsmaMacPhy made a 17th transmission attempt before they dropped a frame whose attempts all collided. IEEE 802.3 allows 16 (attemptLimit, clause 4.2.3.2.5), and both modules now stop there. The backoff before each retransmission does not change. This changes the results of half-duplex simulations in which a frame collides 16 times in a row.

EthernetCsmaMac records two new statistics. packetPendingDelay is the time from the start of the first transmission attempt of a frame to the start of the attempt that succeeds; EthernetPlca records a statistic of the same name, so the medium access delay of a 10BASE-T1S link can be compared with and without PLCA. packetDropRetryLimitReached counts the frames that the MAC drops after 16 colliding attempts, as the IEEE 802.11, IEEE 802.15.4 and CsmaCaMac MACs do.

The new protocol ethernetmacnofcs ("Ethernet MAC without FCS") is an Ethernet MAC frame without an FCS at its end, for example a frame that a portal or a tunnel carries without one. Before, such a frame could not be labeled correctly: packet filters, the packet printer and PCAP recording failed on it, or they dissected the payload 4 bytes short. A module that removes the FCS of a frame changes its protocol to ethernetmacnofcs, and a module that adds an FCS changes it back to ethernetmac. Packet filter expressions reach the fields of such a frame as ethernetmacnofcs.dest, or as EthernetMacHeader.dest for both kinds of frame. PcapRecorder records such frames with the link type LINKTYPE_ETHERNET.

An EthernetSwitch or a TsnSwitch on the modular EthernetLayer now forwards a frame whose EtherType has no protocol in INET, as an IEEE 802.1D or 802.1Q bridge does. Such frames come from emulation, from PCAP replay, or from modules that make their own MAC header. EthernetMacHeaderChecker and Ieee8021qTagEpdHeaderChecker have the new parameter acceptUnknownEtherTypes, false by default, which EthernetSwitch sets to true. The payload of such a frame has the protocol Protocol::unknown, and its EtherType goes with it in an EtherTypeInd tag; the header inserters write the EtherType back from an EtherTypeReq. A host still drops such frames.

The packet inspector of Qtenv, the log and the other printouts show the EtherType fields (typeOrLength and tpid) in hex with the name of the protocol, for example 0x88a8 (IEEE 802.1Q S-TAG) instead of 34984. A typeOrLength value that is a length is shown as a decimal number, for example 46 (length). The values of the fields do not change, so packet filter expressions such as ethernetmac.typeOrLength == 0x8100 do not change.

The algorithm of a TCP connection is its submodule

Each TCP connection now creates its congestion control algorithm (TcpNewReno, TcpCubic, DcTcp and the others) as its submodule algorithm, for example tcp.conn-3.algorithm, of the NED type that tcpAlgorithmClass names. Each algorithm has a simple module type of the same name in inet.transportlayer.tcp.flavours, which extends the new TcpAlgorithm and holds the parameters of the algorithm. Qtenv shows the algorithm of a running connection with its parameters and its state variables. The connection keeps the timers and the signals of the algorithm, so the results do not change.

The parameters that only one algorithm reads moved from Tcp to the type of that algorithm, so their ini keys change:

  **.tcp.cubicBeta              -> **.tcp.conn-*.algorithm.beta
  **.tcp.cubicC                 -> **.tcp.conn-*.algorithm.c
  **.tcp.cubicFastConvergence   -> **.tcp.conn-*.algorithm.fastConvergence
  **.tcp.cubicTcpFriendliness   -> **.tcp.conn-*.algorithm.tcpFriendliness
  **.tcp.cubicCntClamp          -> **.tcp.conn-*.algorithm.cntClamp
  **.tcp.cubicDelta             -> **.tcp.conn-*.algorithm.delta
  **.tcp.hystart...             -> **.tcp.conn-*.algorithm.hystart...
  **.tcp.dctcpGamma             -> **.tcp.conn-*.algorithm.g

dctcpGamma was a parameter of INET 4.7, and Tcp no longer has it. The parameters of CUBIC and HyStart were not in a release. LinuxTcp and LegacyTcp turn HyStart on with a pattern assignment for the algorithms of their connections. TcpVegas has the new parameters alpha, beta and gamma, with the values of its former constants as defaults.

A TCP algorithm implemented outside INET needs a simple module type that extends TcpAlgorithm, and Define_Module() in place of Register_Class(); without the type, the connection stops with an error. Its initialize() is now initializeAlgorithm(), and the cancelEvent() helper of TcpAlgorithmBase is now cancelTimer(). See the migration guide.

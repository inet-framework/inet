IPv6 Neighbor Discovery and address autoconfiguration

A router now answers every Router Solicitation. Before, an interface answered the first one and ignored the next ones until its next periodic Router Advertisement, so a host that sent its solicitation second got no global address and could not be reached, without an error. The first three Router Advertisements of an interface now come at most 16 s apart (MAX_INITIAL_RTR_ADVERT_INTERVAL, RFC 4861 section 6.2.4); before, the first periodic advertisement came 198 to 600 s after the start. The advertising timer starts when the router has booted (routerBootupTime), a multicast answer to a solicitation restarts it, and a router keeps the minimum delay between advertisements of section 6.2.6.

Datagrams and Router Advertisements take the values of RFC 4861. A datagram whose transport gives no hop limit leaves with the CurHopLimit of its outgoing interface, 64 by default or the Cur Hop Limit of the last Router Advertisement; before, it left with the constant 30. The defaults of Ipv6RoutingTable are advCurHopLimit = 64 (it was 30) and advLinkMtu = 0 (it was 1280), and a Router Advertisement carries an MTU option only when advLinkMtu is not 0, so with the defaults it is 8 octets shorter; set advLinkMtu to keep the option. A host sends datagrams of at most the LinkMTU that an MTU option sets, from 1280 to the MTU of the interface, which is the default (it was 1280). Address resolution and the probes of Neighbor Unreachability Detection wait the RetransTimer that a Router Advertisement sets. The default of AdvRetransTimer is 0 (it was 1), so a router with the default leaves the field unspecified; before, Duplicate Address Detection read that field, in milliseconds, as seconds.

A host processes a Router Advertisement also during Duplicate Address Detection: the Default Router List and the parameters of the link follow it, and its prefixes wait until the detection ends. A host accepts a Router Advertisement without a Prefix Information option, which RFC 4861 section 6.1.2 does not require. With dupAddrDetectTransmits = 0, an interface no longer sends a Neighbor Solicitation before the address becomes permanent. The new parameter sendGratuitousNa of Ipv6NeighbourDiscovery, false by default, lets each address announce itself with an unsolicited Neighbor Advertisement when Duplicate Address Detection completes. A solicited Neighbor Advertisement that makes a Neighbour Cache entry REACHABLE restarts its ReachableTime, so such runs send fewer probes. A Redirect carries the Target Link-Layer Address option and the Redirected Header option (the new class Ipv6NdRedirectedHeader), with as much of the invoking packet as fits into 1280 octets.

Ipv6NetworkConfigurator now assigns a global address as tentative when the interface does Duplicate Address Detection (dupAddrDetectTransmits above 0), and Neighbor Discovery tests it when the node has booted. The address becomes usable about one to two seconds after the boot; set dupAddrDetectTransmits to 0 to keep the old behavior. An address whose valid lifetime ends is now removed at that instant, with the ipv6AddressRemoved signal, and the interface leaves its solicited-node group; before, the address stayed the preferred source address.

Three defects that stopped or corrupted a simulation are corrected. Duplicate Address Detection of an address stops when the address is removed; before, it completed for an address that the interface no longer had. A second start of Router Discovery on an interface restarts the running process; before, two processes ran side by side, and the run stopped with "Cannot cancel another module's self-message", heap corruption or a segmentation fault. With Ipv6NetworkConfigurator, a router interface holds its configured global address once; before, Ipv6NeighbourDiscovery assigned it a second time, with a second ipv6AddressAssigned and interfaceIpv6ConfigChanged signal.

Ipv6TunnelInterface did not declare the isWireless parameter, so Ipv6NetworkConfigurator joined all tunnel interfaces of the network into one wireless LAN, and a tunnel entry point could get a route to its own exit point through the tunnel. Each tunnel interface is now a link of its own, also for Ipv4NetworkConfigurator and NextHopNetworkConfigurator, so the results of simulations with more than one Ipv6TunnelInterface change. Ipv6NetworkConfigurator dumps a host that is left to dynamic configuration as addr=dynamic.

These corrections change the trajectories and the fingerprints of IPv6 simulations: the hop limit of most datagrams changes, the Router Advertisements are shorter and come earlier, and configured addresses are tested, for example in the MLD, Mobile IPv6, PMIPv6, OSPFv3 and PIM examples over IPv6.

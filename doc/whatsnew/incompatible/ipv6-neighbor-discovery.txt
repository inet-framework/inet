IPv6 Neighbor Discovery and address autoconfiguration

A router now answers every Router Solicitation. Before, an interface answered the first one and ignored the next ones until its next periodic Router Advertisement (default 200 to 600 s), so a host that sent its solicitation second got no global address and could not be reached, without an error. A router also keeps the minimum delay between Router Advertisements of RFC 4861 section 6.2.6 (MIN_DELAY_BETWEEN_RAS) when it answers.

A host accepts a Router Advertisement without a Prefix Information option, which RFC 4861 section 6.1.2 does not require, and takes the router as its default router. With dupAddrDetectTransmits = 0, an interface no longer sends a Neighbor Solicitation before the address becomes permanent (RFC 4862 section 5.4). The new parameter sendGratuitousNa of Ipv6NeighbourDiscovery, false by default, lets each address announce itself with an unsolicited Neighbor Advertisement when Duplicate Address Detection completes (RFC 4861 section 7.2.6). A solicited Neighbor Advertisement that makes a Neighbour Cache entry REACHABLE now restarts its ReachableTime, as RFC 4861 section 7.3.3 requires, so such runs send fewer probes.

Three defects that stopped or corrupted a simulation are corrected. Duplicate Address Detection of an address now stops when the address is removed; before, it completed for an address that the interface no longer had, and a debug build stopped with an assertion. A second start of Router Discovery on an interface restarts the running process; before, two processes ran side by side, and the run stopped with "Cannot cancel another module's self-message", heap corruption or a segmentation fault. With Ipv6NetworkConfigurator, a router interface holds its configured global address once; before, Ipv6NeighbourDiscovery assigned it a second time, so getNumAddresses() and interface dumps counted it twice, and the ipv6AddressAssigned and interfaceIpv6ConfigChanged signals of the second assignment are gone. Ipv6FlatNetworkConfigurator, which assigns no global address, is not affected.

Ipv6TunnelInterface did not declare the isWireless parameter, so each tunnel interface counted as a wireless interface. Ipv6NetworkConfigurator therefore joined all tunnel interfaces of the network into one wireless LAN, and a tunnel entry point could get a route to its own exit point through the tunnel, which encapsulated each packet again and again; also, explicit addresses on two tunnel interfaces had to share one prefix. Each tunnel interface is now a link of its own, also for Ipv4NetworkConfigurator and NextHopNetworkConfigurator. The results of simulations that use one of these configurators with more than one Ipv6TunnelInterface change. Ipv6NetworkConfigurator dumps a host that is left to dynamic configuration as addr=dynamic.

These corrections change the trajectories and the fingerprints of IPv6 simulations, for example of the MLD, Mobile IPv6, PMIPv6, OSPFv3 and PIM examples over IPv6.

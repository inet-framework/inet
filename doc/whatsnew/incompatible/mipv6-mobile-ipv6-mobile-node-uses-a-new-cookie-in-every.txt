A Mobile IPv6 mobile node uses a new cookie in every test init message

Every Home Test Init carried the Home Init Cookie 11 and every Care-of Test
Init the Care-of Init Cookie 21, retransmissions included, so a mobile node
could not tell the answers to two transmissions apart. Each transmission
now carries a new random 64-bit cookie (RFC 6275 Sections 5.2.3 and 11.8),
drawn from random number generator 0 of the Mipv6 module. This changes the
results of simulations that use route optimization.

BindingUpdateList::addOrUpdateBUL() takes the cookie as uint64_t, as
described in the migration guide.

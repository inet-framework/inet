A network interface that is deleted during the run leaves the interface tables and the dispatchers

A network interface module that was deleted other than through InterfaceTable::deleteInterface(), for example with the delete-module command of ScenarioManager, stayed in the interface table as a dangling pointer, and the next lookup used the deleted object: a switch whose port was deleted crashed at the next frame. MessageDispatcher also kept the gate of the interface, so a packet for the interface went to a gate that was no longer connected. Now NetworkInterface::preDelete() calls the new pure virtual method IInterfaceTable::removeInterface(), and it unregisters the interface from the dispatchers. A packet for a deleted interface fails with "Unknown network interface". MacForwardingTable now also removes the entries of a deleted interface; before, they stayed until they aged out, and static entries stayed forever.

The modules that listen to the interface signals of a node, for example the node configurators, the routing tables, IGMP, MLD, RIP, OSPF, EIGRP, PIM, MRP and DhcpClient, now ignore the interfaces of other interface tables in the node. Interface ids of different tables can be equal, so before, the deletion of an interface of a nested table could remove the state of an interface of the node.

InterfaceTable no longer stops the simulation with "getIndex(): Gate is not member of a gate vector" when an interface is connected to scalar ifIn and ifOut gates. A scalar gate counts as index -1 in the check that the two gates have the same index.

This change requires the modification of C++ code that implements IInterfaceTable outside INET. IInterfaceRegistrationListener has the new method handleUnregisterInterface() with an empty default body, so other listeners compile as before.

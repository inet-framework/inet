IGMP and MLD follow RFC 9776 and RFC 9777

The messages follow the RFCs on the wire. IGMPv3 and MLDv2 Queries carry the QRV and the QQIC of their querier; before, both fields were 0. IGMP Reports and Leaves, also those of the IGMPv2 mode, have the precedence Internetwork Control (Type of Service 0xc0). Every MLD message carries the Router Alert option of RFC 2711 in a Hop-by-Hop Options header (the new class Ipv6RouterAlertOption), and a multicast router delivers a multicast datagram locally when it carries the option; before, it delivered each ICMPv6 multicast datagram locally. The Ipv6 module counts the extension headers that a sender requests with an Ipv6ExtHeaderReq tag in the Payload Length; before, the receiver cut off the end of the message. In the "computed" checksum mode, the checksum of each ICMPv6 message covers the pseudo-header of the IPv6 datagram (RFC 4443 section 2.3), with the new Icmpv6::insertComputedChecksum(); before, a real node or a capture tool rejected each message. The "declared" mode, the default, does not change.

Every MLD message leaves from the link-local address of its interface (RFC 2710 section 3, RFC 9777 section 5); before, it left from the global address. Before Duplicate Address Detection has tested the link-local address, a Report or a Done leaves from the unspecified address (RFC 3590 section 4, RFC 9777 section 5.2.14), and the node reports its groups again when the address becomes valid. A node discards a Report or a Done from the unspecified address, and a router does not forward a multicast datagram from the unspecified address (RFC 4291 section 2.5.2). The querier of an interface starts when the interface has a tested link-local address, up to about 2 s after the start. An IPv6 interface joins the solicited-node multicast group of each of its unicast addresses when it gets the address, before the detection, so with MLD on, a node reports these groups too. Ipv6InterfaceData emits interfaceIpv6ConfigChanged when an address becomes tentative or valid.

Some defaults take the values of the RFCs. The unsolicitedReportInterval of Igmpv3 and Mldv2 is 1 s (it was 10 s), and their groupMembershipInterval is 270 s with the other defaults (it was 260 s). The timer of a router for an older host has the new parameters olderHostPresentInterval of Igmpv3 and olderVersionHostPresentInterval of Mldv2, 260 s with the defaults. The IGMPv2 or IGMPv1 mode of an Igmpv3 host lasts for the Older Version Querier Present Interval, 350 s with the defaults, and the MLDv1 mode of an Mldv2 node 260 s; before, both lasted 255 s.

Hosts and routers follow the state machines of the RFCs. A second change of a group merges the pending State-Change Report. In the IGMPv1, IGMPv2 and MLDv1 modes, a host delays its answer to a Query by a random time, stops it when it hears the Report of another member, repeats the Report of a join, and sends a Leave or a Done only when it sent the last Report; before, each member answered at once. A change of the compatibility mode cancels the pending timers. An answer to a Query leaves out the groups that the host left, and records with no sources. The S flag of a specific Query comes from the lowered timer, and the specific Queries keep their retransmission state, so a Report no longer ends them, and a source that the last member blocks stops after the Last Member Query Time; before, it stayed forwarded up to 260 s.

IPv4 and IPv6 forward a multicast datagram onto a leaf interface only when the interface has a listener of its source, so the source lists of IGMPv3 and MLDv2 now have an effect on the data. Before, a listener of the group was enough, and Ipv4InterfaceData::hasMulticastListener(group, source) gave the opposite answer.

The new parameter routerVersion of Igmpv3 (default 3) selects the IGMPv2 or IGMPv1 mode of a router, and an older General Query puts the router into that mode on its interface, with a warning. routerVersion of Mldv2 (default 2) selects the MLDv1 mode of a router; RFC 9777 leaves that mode to the administrator, so an MLDv1 Query gives only a warning. An Mldv1 node ignores an MLDv2 Report, and reads an MLDv2 Query as an MLDv1 Query; before, both stopped the simulation. With computed checksums, PimChecksumInsertionHook no longer crashes on a datagram with an IPv6 extension header.

These corrections change the trajectories and the fingerprints of IGMP, MLD and PIM simulations, and of IPv6 simulations with MLD.

IGMP and MLD corrections

An IGMPv3 Query now carries the QRV and the QQIC of its querier: the Robustness Variable (0 above 7) and the code of the Query Interval (RFC 9776 sections 4.1.6 and 4.1.7). Before, both fields were 0. An MLDv2 Query now carries them too (RFC 9777 sections 5.1.8 and 5.1.9).

An IGMPv3 Report and Leave, also the IGMPv2 messages of a host in IGMPv2 mode, now leave with the precedence of Internetwork Control, Type of Service 0xc0 (RFC 9776 section 4), as the Queries already did.

Every MLD message, of Mldv1 and of Mldv2, now leaves from the link-local address of its interface (RFC 2710 section 3, RFC 9777 section 5), once Duplicate Address Detection has tested it. Before, it left from the global address. So the querier of an interface now starts when the interface has a tested link-local address, up to about 2 seconds after the start, and a Report or a Done waits until then. Ipv6InterfaceData now emits the interfaceIpv6ConfigChanged signal when an address becomes tentative or valid.

The Ipv6 module now counts the extension headers that a sender asks for with an Ipv6ExtHeaderReq tag in the Payload Length of the datagram (RFC 8200 section 3). Before, the Payload Length counted only the upper-layer message, so the receiver cut off the end of the message.

Every MLD message, of Mldv1 and of Mldv2, now carries the Router Alert option of RFC 2711 in a Hop-by-Hop Options header (RFC 2710 section 3, RFC 9777 section 5). The new Ipv6RouterAlertOption class holds the option, and the serializer reads and writes it. A multicast router now delivers a multicast datagram locally when the datagram carries the option. Before, it delivered every ICMPv6 multicast datagram locally, to receive the MLD messages.

In the "computed" checksum mode, the checksum of every ICMPv6 message now covers the pseudo-header of the IPv6 datagram (RFC 4443 section 2.3): MLD, Neighbor Discovery, Echo and the error messages. The Ipv6 module computes it when the source address is final, with the new Icmpv6::insertComputedChecksum(), and Icmpv6 checks it with the addresses of the datagram. Before, the checksum covered the message only, so a real node or a capture tool rejected every message. The "declared" mode, the default, does not change.

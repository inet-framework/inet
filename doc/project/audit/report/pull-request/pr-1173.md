## Findings

### F-1 — Commit 1 reverses #1172's commit 1, across the stack

**Rules:** [PR-SPLIT-WHITESPACE](../../../rule/pull-request.md#pr-split-whitespace),
[PR-REQ-TOPIC](../../../rule/pull-request.md#pr-req-topic). **Finding — and it belongs to #1172.**

#1172's commit 1 — *"remove a trailing blank line from the receiver header"* — deletes one line
from `Ieee80211Receiver.h`. This pull request's commit 1 — *"preserve receiver header trailing
spacing"* — adds one back. Each pull request is consistent on its own, which is why neither audit
alone can see it; only the two merged in order add and then remove the same line, and the net
result is one more blank line than the tree had, which neither message describes.

Each is a correct whitespace commit by the letter of the rule, and [#1172](pr-1172.md) praised its
one for that. But a whitespace commit exists to be *verified at a glance and forgotten*, and a
whitespace commit that a later commit reverses was not wanted. **Drop #1172's commit 1**; this one
then has nothing to reverse and goes with it. Two commits fewer, and the file as it was.

It is a stack finding rather than a series finding: [PR-SERIES-ORDER](../../../rule/pull-request.md#pr-series-order)
speaks of a correction *inside* a series, and inside this series there is none.

### F-2 — A project-wide baseline repair is riding in a topic branch

**Rules:** [PR-SPLIT-DRIVEBY](../../../rule/pull-request.md#pr-split-driveby),
[PR-SPLIT-BASELINE](../../../rule/pull-request.md#pr-split-baseline). **Finding.**

Commit 10 rewrites 72 fingerprint values in `tests/fingerprint/store.json`. Its message is precise
and its claim checks out: the CSV baselines had already accepted those values before this branch —
`examples.csv` at the merge base already reads `d3d9-7959` for `geometry`, exactly as the message
says — and the JSON store had fallen behind. This is not a baseline that this branch's source moves.
It is a pre-existing inconsistency between two baseline formats, and the gate flags it only because
it happens to follow a source commit; the judgment call in
[review-a-pull-request.md](../../../guide/review-a-pull-request.md) §3 is that a baseline commit no
source commit causes is correct on its own.

**As a commit it is right. As a passenger it is wrong.** Of the 72 rows, 33 are in 802.11
directories (`examples/wireless/nic` alone is 21), **22 are in directories this branch never
touches** — `showcases/visualizer/canvas` (12), `examples/manetrouting/gpsr` and `dymo` (5 each) —
and 11 could not be attributed by a context window. A reader who bisects a visualizer
fingerprint into an 802.11 HT branch will not thank anyone. A repair of project-wide
staleness is its own pull request, one commit, mergeable today, and it would make the fingerprint
gate honest for everyone rather than for this branch.

**What would close it:** move commit 10 to its own pull request. The message can go with it as it
stands.

**A note for our own gate.** `check-commits.sh` cannot tell "a baseline this source commit moved,
left in a separate commit" from "a baseline nothing here moved". The first should be squashed; the
second should be its own pull request. Both print the same line today.

### F-3 — No release note, for the fifth pull request running

**Rules:** [RR-WHATSNEW](../../../rule/release.md#rr-whatsnew),
[RR-BREAK-MIGRATE](../../../rule/release.md#rr-break-migrate). **Finding.**

`WHATSNEW` is untouched. Four things break for code outside the tree — the three from #1172, and one
more from the AP side:

| What breaks | Who it reaches |
|---|---|
| `Ieee80211EnumeratedBand`'s two-argument constructor is removed | anyone defining a band |
| `Ieee80211ModeSet::Ieee80211ModeSet` gains a `bool` | anyone constructing a mode set directly |
| `IIeee80211Band::printToStream()` becomes pure | an out-of-tree band that relied on the default — the correct break |
| `Ieee80211MgmtAp::receiveSignal(…, intval_t, …)` is removed; `sendManagementFrame` gains a `uint64_t` | an out-of-tree management model extending the AP |

The recommendation stands from [#1172 F-1](pr-1172.md): a `T3` check in `check-commits.sh` that
fails a branch which removes or re-signs a public symbol and touches no `WHATSNEW`. The change
summary already computes the list.

## Notes

Advisory; worth seeing, not worth a round trip. See
[audit/README.md](../../README.md) §*How severe is a finding*. From the summary's `--usage` pass —
questions [AR-EXT-MINIMAL-SURFACE](../../../rule/architecture.md#ar-ext-minimal-surface) and
[AR-EXT-VIRTUAL-IS-A-PROMISE](../../../rule/architecture.md#ar-ext-virtual-is-a-promise) put to
every new member. Most are inherited from #1172; the AP side adds two.

- **6 new public functions that nothing calls** — four setters and a getter on
  `HtNegotiationFailure`, a value built once; `Ieee80211Mib::updateLocalHtCapabilities`;
  `Ieee80211ModeSet::getMaximumChannelWidth`. Same six as #1172.
- **4 new public functions called only from tests** — `isReassociation`,
  `getFastestLegacyOperationalMode`, `getHtMcsSupported`, `getHtShortGuardIntervalChannelWidths`.
  Two fewer than #1172: the AP side now calls `hasPrimaryChannel` and `requirePrimaryChannel`.
- **15 new virtuals that nothing overrides** — #1172's 13 plus `Ieee80211MgmtAp::clearPendingAssociation`
  and `createAssociationTransactionId`. For each: *if a user overrode this, what would they be trying
  to do?* A sentence in the comment keeps the `virtual`; nothing keeps it a `private` non-virtual.

## On the stack

GitHub shows this pull request as 10 commits because its base is #1172's branch; against master it
is 24. If #1172 merges first, #1173 rebases cleanly — the eight re-created commits beneath it are
byte-identical. If they are reviewed as one, #1172 is the STA side and this is the AP side, and F-1
says something about the first that its own audit could not: its whitespace commit was later
reversed.

**A note on this report's own method.** The first version of this report numbered the commits 1–24
against master and called the reversal "commit 15 undoes commit 1, in the same series". That was
the wrong frame: the pair straddles two pull requests. A stacked pull request is audited in its own
numbering, against its own base, and a finding that only the whole stack shows is named as such.

## Findings

### F-1 — No release note, for the fourth pull request in a row

**Rules:** [RR-WHATSNEW](../../../rule/release.md#rr-whatsnew),
[RR-BREAK-MIGRATE](../../../rule/release.md#rr-break-migrate). **Finding.**

`WHATSNEW` is untouched. Three things break for code outside the tree:

| What breaks | Who it reaches |
|---|---|
| `Ieee80211EnumeratedBand`'s two-argument constructor is removed | anyone defining a band |
| `Ieee80211ModeSet::Ieee80211ModeSet` gains a `bool` | anyone constructing a mode set directly |
| `IIeee80211Band::printToStream()` becomes pure | an out-of-tree band that relied on the default — **the right break**, and still a break |

The third is the one worth a sentence in the note, because it is *deliberate*: it is the rule's own
prescription, and a user who hits the compile error should be able to read why.

**This is now the fourth pull request in a row with this finding** — #1154 and #1172 from this
author, #1155 from another. At that point the finding is about the rule, not the authors: the
obligation is not visible at the moment it is incurred. The change summary already computes the exact
list a `T3` check would need — *removed*, *signature changed*, *pure: gained* — so
[check-commits.sh](../../../enforcement/check-commits.sh) could fail a branch that removes or re-signs
a public symbol and touches no `WHATSNEW`. That is a ten-line addition and it would have caught all
four.

**What would close it here:** a `WHATSNEW` entry naming the three rows above.

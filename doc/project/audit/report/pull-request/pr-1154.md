## What changed since the first audit

Eleven commits: two `ethernet:` repairs at the front, nine `ieee80211:` at the end.

**One of them undoes a coupling the earlier head added.** The first audit's summary showed
`Ieee80211MgmtAp` gaining `public IFrameTransmissionCallback` as a base. `ieee80211: replace frame
transmission callback with signal` removes it, and the reason is the right one:

> The 1-to-1 typed callback `IFrameTransmissionCallback` coupled `Ieee80211Mac` directly to a single
> management peer (`Ieee80211MgmtAp`), preventing non-behavioral observers (result filters,
> statistics, trace visualizers) from observing terminal transmission outcomes.

A signal with a details object replaces it, and three statistics are declared on top. That is
[D-OBSERVE](../../../design/decisions.md#d-observe) and
[AR-OBS-SIGNALS](../../../rule/architecture.md#ar-obs-signals) arrived at from the inside: the author
found the callback limiting for the same reason the rule forbids it.

The interface summary is smaller than the earlier head's despite eleven more commits — **2 removed
against 4, 4 changed against 5** — because the callback and a serializer override went away.

**The two `ethernet:` commits are preparation in another subsystem**, each in its own commit with its
own unit test, ahead of the 802.11 work that needs them. That is
[PR-SPLIT-UPSTREAM](../../../rule/pull-request.md#pr-split-upstream) again, in a second subsystem.

## Findings

### F-1 — No release note, and this change removes and re-signs public API

**Rules:** [RR-WHATSNEW](../../../rule/release.md#rr-whatsnew),
[RR-BREAK-MIGRATE](../../../rule/release.md#rr-break-migrate). **The one that matters, and it
survived the rewrite.**

`WHATSNEW` is still untouched, at 32 commits and 112 files. What a user or an out-of-tree model meets
without warning:

| What breaks | Who it reaches |
|---|---|
| `Ieee80211ModeSet::Ieee80211ModeSet` gains three arguments | anyone constructing a mode set directly |
| `TxopProcedure::getTxopLimit` takes a `PhyType` instead of an `IIeee80211Mode *` | an out-of-tree TXOP procedure |
| `Ieee80211MgmtAp::sendManagementFrame` gains a `uint64_t` | an out-of-tree management model extending the AP |
| `Ieee80211EnumeratedBand`'s two-argument constructor is removed | anyone defining a band |
| `IFrameTransmissionCallback` is removed in favour of a signal | anyone who adopted it at the earlier head |
| 37 fingerprint rows move | every 802.11 simulation whose trajectory is recorded |

The last one is documented four times over, in the commit messages that carry it. The others are
documented nowhere a user looks.

This is the same gap as [#1155](pr-1155.md) F-2, in a different subsystem, by a different author, on
the same day. **Two independent workstreams reaching the same omission is a sign the rule is not
visible enough**, not that two authors were careless. Worth a line in
[guide/contribute-a-change.md](../../../guide/contribute-a-change.md) step 8, and worth a `T3` check
that asks for a `WHATSNEW` entry when a branch removes or re-signs a public symbol — the change
summary already computes exactly that list.

**What would close it:** a `WHATSNEW` entry naming the six rows above.

### F-2 — Two small message and split faults, unchanged since the first audit

**Rules:** [PR-MSG-STANDALONE](../../../rule/pull-request.md#pr-msg-standalone),
[PR-SPLIT-ONE-CHANGE](../../../rule/pull-request.md#pr-split-one-change). **Small.**

**Three messages cite a commit by its position in the series** — `C01`, `C02`, `C17`. After a rebase
that position means nothing, and this branch has now been rebased once already. Name the thing rather
than its position.

**The `queueing:` commit carries a passenger.** Its body says *"Retake the selected packet after
removal and before drop processing. **Also** keep the streaming push API publicly accessible through
`PacketQueueBase`."* The subject describes the first; the second is a visibility change on a
different file, and it is the one an out-of-tree queue would notice.

## What the change is

Read from the summary and the series, the workstream has six movements:

1. **Preparation outside TCP** — a chunk-splitting repair, PPP brought to RFC 1661, a pcap link type.
2. **A split architecture** — `TcpBaseAlg` becomes `TcpAlgorithmBase`, `TcpTahoeRenoFamily` becomes
   `TcpClassicAlgorithmBase`, and congestion control and loss recovery become separate interfaces.
   Every classic flavour is re-based onto them.
3. **New algorithms** — RFC 5681, RFC 6582, RFC 6675, and `TcpCubic` (RFC 9438) with HyStart.
4. **Modern loss recovery** — RFC 8985 time-based loss, reordering, RFC 6937 PRR, RFC 5682 F-RTO,
   tail loss probe.
5. **New capabilities** — Fast Open, Accurate ECN, keepalive, path MTU discovery, PSH boundaries.
6. **Modernized defaults**, and the fingerprints they move.

The summary makes the shape legible at once: **69 new NED parameters, 19 new message types, 241 new
message fields, 174 new public functions, 54 new extension points** — against **41 public functions
and 15 message fields removed**.

## Findings

### F-1 — The branch edits the sealed `common/packet/`, and the pull request does not say so

**Rules:** [PR-REQ-ARCH](../../../rule/pull-request.md#pr-req-arch),
[SR-FOLDER-RECURSIVE](../../../rule/sealing.md#sr-folder-recursive). **Blocking.**

`common/packet/` is the one sealed path in the tree ([seal-list.md](../../seal-list.md)), sealed
recursively. Three files under it are modified, in two commits:

| File | Commit |
|---|---|
| `chunk/BitCountChunk.cc` | `ed742203a8` packet: keep the fill byte when splitting |
| `chunk/ByteCountChunk.cc` | `ed742203a8` |
| `recorder/PcapRecorder.cc` | `21d34de9e8` pcap: record PPP traces as LINKTYPE_PPP |

[PR-REQ-ARCH](../../../rule/pull-request.md#pr-req-arch) asks that a change touching a sealed path
state the permission for it. Nothing in the branch does.

**Two things follow, and they point in opposite directions.** The seal is a claim that the subtree was
audited and complied on 2026-07-20; a change to it makes that claim stale, and
[SR-RULE-CHANGE-STALES](../../../rule/sealing.md#sr-rule-change-stales) reasoning applies just as
much to a change in the code as to a change in a rule. But this registry already records that
**the `common/packet/` seal does not satisfy [SR-AUDIT-FIRST](../../../rule/sealing.md#sr-audit-first)**:
it was recorded over two `AV-ORG` clusters that are still `Open (decide)`.

**What would close it:** decide the seal first. Either resolve the two clusters and re-audit the
subtree after this change, or take the seal off until it can be earned. Blocking a well-argued
three-line chunk repair behind a seal that our own ledger calls invalid would be the worst of both.

### F-2 — No release note, for a change that breaks users in four different ways

**Rules:** [RR-WHATSNEW](../../../rule/release.md#rr-whatsnew),
[RR-BREAK-MIGRATE](../../../rule/release.md#rr-break-migrate),
[RR-DEPRECATE-FIRST](../../../rule/release.md#rr-deprecate-first). **Blocking.**

`WHATSNEW` is not touched. `doc/src/` gains 15 lines, none of which mention a break. The summary
lists four classes of break that a user meets without warning:

| What breaks | Who finds out, and how |
|---|---|
| the `sndNxt` **signal and statistic** are removed, from `tcp` and `tcp_lwip` | a user's `.anf` chart and result-analysis script stop producing a series; nothing errors |
| `TcpBaseAlg` → `TcpAlgorithmBase` and `TcpTahoeRenoFamily` → `TcpClassicAlgorithmBase` | every TCP algorithm implemented outside INET stops compiling |
| **41 public functions removed**, including the `TcpAlgorithm` callback set | the same audience, at the same moment |
| `PppTrailer` removed, `PppHeader` fields removed | a model or a serializer that reads PPP on the wire |
| the `tcpAlgorithmClass` default list changes; the modernized defaults move 53 fingerprints | every unconfigured TCP simulation produces a different packet sequence |

The last one is stated superbly in a commit message — *"essentially every simulation carrying TCP
produces a different packet sequence"* — and a commit message is read by whoever reads commit
messages. `WHATSNEW` is where a user deciding whether to upgrade looks.

The rename is also the shape [RR-DEPRECATE-FIRST](../../../rule/release.md#rr-deprecate-first) exists
for. A `using TcpBaseAlg = TcpAlgorithmBase;` alias for one release costs one line and keeps every
out-of-tree flavour compiling while its author moves.

**What would close it:** a `WHATSNEW` entry naming the five rows above, and a deprecation alias for
the two renamed base classes. This is a few hours of writing against sixty-one commits of work
already done; it is the difference between a modernization and a break.

### F-4 — Two baseline-only commits, under a rule that inverted after this branch was written

**Rule:** [PR-SPLIT-BASELINE](../../../rule/pull-request.md#pr-split-baseline). **Contested, and the
content is exemplary.**

`9f40ee337e` and `33e8b0d073` hold fingerprint `.csv` files and nothing else, each following the
source commit that moves them. Under the **current** rule — changed on 2026-09-01, after this branch
was written — a regenerated baseline travels in the same commit as the source change that moves it,
because a source commit without its baselines fails its own fingerprint test and breaks
[PR-SERIES-BUILDS](../../../rule/pull-request.md#pr-series-builds).

**The author followed the rule as it stood.** Under the previous wording these two commits were not
merely allowed, they were required.

What the two commits say is better than the rule asks for either way.
[TR-BASELINE-PROVENANCE](../../../rule/testing.md#tr-baseline-provenance) wants the cause and the
reason; `33e8b0d073` gives the *measurement*: the branch tip was built in a separate workspace and
the full suite run there, **53 rows** move and every one carries TCP traffic, each family named. It
then says what it deliberately did **not** touch, and why.

**What would close it:** squash each into the commit before it, keeping both messages. Two rebases.

### F-5 — A rename commit that also edits 25 files

**Rule:** [PR-SPLIT-MOVE](../../../rule/pull-request.md#pr-split-move). **Real, and its cost is
already visible.**

`ed2c8df034` *"tcp: move the classic flavours onto the split architecture"* renames three files and
edits twenty-five others in the same commit:

```
R056  flavours/TcpBaseAlg.h              → flavours/TcpAlgorithmBase.h
R053  flavours/TcpBaseAlgState.msg       → flavours/TcpAlgorithmBaseState.msg
R064  flavours/TcpTahoeRenoFamilyState.msg → flavours/TcpClassicAlgorithmBaseState.msg
```

The similarity scores are the finding: **53%, 56% and 64%.** Git only just detected these as renames
at all, because the files were rewritten in the same commit that moved them. A few more edited lines
and they would have shown as a delete plus an add, and the `git blame` history of the three most
central files in the TCP flavour hierarchy would have ended there.

**What would close it:** a rename-only commit first, then the rewrite. The rule exists for exactly
this file.

## What this series does well

**The test ratio.** 69 module tests and 7 unit tests out of 183 files. For a workstream that adds ten
RFCs' worth of behavior, the tests are the deliverable as much as the code is.

**Fingerprint honesty.** `33e8b0d073` does not only justify what it changed; it records that **296
rows of master's baseline already mismatched** before this branch, across OSPF, QUIC, DiffServ, UDP,
MIPv6 and the visualizer, and leaves them alone deliberately. That is a project-level fact worth
acting on separately, and this pull request is where it was measured.

**A readable arc across 61 commits.** Preparation outside TCP, then the architecture, then the
algorithms that need it, then the defaults, then the fingerprints. A reviewer can take it in six
sittings, which is the most that can be asked of a change this size.

## Not verified

- **PR-SERIES-BUILDS**, over 61 commits. Needs a per-commit CI build

  the one this change most needs.

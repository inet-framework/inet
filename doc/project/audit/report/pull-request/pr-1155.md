## Findings

Numbering is carried from the first audit, so a citation of `F-1` still means the same thing.

### F-1 — The branch edits the sealed `common/packet/`, and does not say so

**Rules:** [PR-REQ-ARCH](../../../rule/pull-request.md#pr-req-arch),
[SR-FOLDER-RECURSIVE](../../../rule/sealing.md#sr-folder-recursive). **Blocking. Unchanged.**

Three files under the one sealed path, in two commits: `chunk/BitCountChunk.cc`,
`chunk/ByteCountChunk.cc` (`ed742203a8`), `recorder/PcapRecorder.cc` (`21d34de9e8`). No permission is
stated.

**And the seal is still not one this registry can defend.** Ten days on, `common/packet/` remains
sealed over `AV-ORG-01` and `AV-ORG-02`, both still `Open (decide)` — which
[SR-AUDIT-FIRST](../../../rule/sealing.md#sr-audit-first) forbids. Blocking a three-line chunk repair
behind a seal our own ledger calls invalid is still the worst of both. **Decide the seal.**

### F-2 — No release note, for a change that breaks users four ways

**Rules:** [RR-WHATSNEW](../../../rule/release.md#rr-whatsnew),
[RR-BREAK-MIGRATE](../../../rule/release.md#rr-break-migrate),
[RR-DEPRECATE-FIRST](../../../rule/release.md#rr-deprecate-first). **Blocking. Unchanged.**

`WHATSNEW` untouched; `doc/src/` gains 15 lines, none of which mention a break. The `sndNxt` signal
and statistic are removed; `TcpBaseAlg` and `TcpTahoeRenoFamily` are renamed, which stops every
out-of-tree TCP algorithm compiling; 41 public functions are removed; `PppTrailer` is removed; the
modernized defaults move 53 fingerprints.

Two things are worth adding since the first audit. **A `using TcpBaseAlg = TcpAlgorithmBase;` alias
for one release** costs one line and satisfies
[RR-DEPRECATE-FIRST](../../../rule/release.md#rr-deprecate-first). And **this finding has since
appeared in four more pull requests** — [#1154](pr-1154.md), [#1172](pr-1172.md),
[#1173](pr-1173.md), [#1145](pr-1145.md) — from two authors, and once correctly did *not* appear
([#1175](pr-1175.md)). Five occurrences say the obligation is not visible where it is incurred. The
change summary computes the exact list a `T3` check would need.

### F-3 — Two baseline-only commits

**Rule:** [PR-SPLIT-BASELINE](../../../rule/pull-request.md#pr-split-baseline). **Finding. The
defence has aged.**

`9f40ee337e` and `33e8b0d073` hold fingerprint `.csv` files and nothing else, each following the
source commit that moves them. The rule inverted on 2026-09-01: a regenerated baseline now travels
in the same commit as the source change, because a source commit without its baselines fails its own
fingerprint test and breaks
[PR-SERIES-BUILDS](../../../rule/pull-request.md#pr-series-builds).

The first audit recorded that the author had followed the rule as it then stood, and that remains
true of the day it was written. Ten days later the branch has not been updated, so the remedy is
simply owed: **squash each into the commit before it, keeping both messages.**

**Keep the messages.** `33e8b0d073` is still the best baseline provenance this audit has seen: the
branch tip was built in a separate workspace and the full suite run there, 53 rows move, every one
carries TCP traffic, each family named — and it records what it deliberately did *not* touch.

### F-4 — A rename commit that also edits 25 files

**Rule:** [PR-SPLIT-MOVE](../../../rule/pull-request.md#pr-split-move). **Finding. Unchanged.**

`ed2c8df034` renames three files at **53 %, 56 % and 64 %** similarity while editing twenty-five
others. Git only just detected them as renames; a few more edited lines and the `git blame` history
of the three central TCP flavour files would have ended there. A rename-only commit first, then the
rewrite.

### F-5 — `ITcpRecovery` holds five no-op default bodies

**Rule:** [AR-ORG-CONTRACT-PURITY](../../../rule/architecture.md#ar-org-contract-purity).
**Finding. New — the rule was written on 2026-09-07, six days after the first audit.**

The head carries **17** interface violations against master's 15. One of the two is
`IIeee80211Band`, which this branch does not touch — master repaired it after this branch's base, so
that difference is staleness, not fault. The other is this branch's own:

```cpp
class INET_API ITcpRecovery {
    virtual bool isDuplicateAck(const TcpHeader *, uint32_t) = 0;
    virtual void receivedAckForUnackedData(uint32_t) = 0;
    virtual void receivedDuplicateAck() = 0;
    virtual void segmentsAcked(uint32_t, uint32_t) {}      // ← five no-op defaults
    virtual void dataSent(uint32_t) {}
    virtual void segmentRetransmitted(uint32_t, uint32_t) {}
    virtual void onRexmitTimeout() {}
    virtual void reoTimeout() {}
};
```

Three classes implement it: `Rfc5681Recovery`, `Rfc6582Recovery`, `Rfc6675Recovery`. A recovery
algorithm that does not care about one of the five gets silence — which is convenient today and is
the exact shape that made `IIndicatorFigure::getNumSeries()` a silent break in
[#1125](pr-1125.md) F-2. Rename one of the five and every out-of-tree recovery keeps compiling with
its override no longer called.

This is a **new interface in a new architecture**, which is the cheapest possible moment to get it
right: there is no out-of-tree implementor yet to break.

**What would close it:** make the five pure and add `{}` to the three implementors where the
behavior really is nothing — three one-line overrides each, and each states its own answer. A
`TcpRecoveryBase` is the alternative if the defaults grow beyond nothing.

**Rule:** [PR-REQ-CLEAN](../../../rule/pull-request.md#pr-req-clean). **Blocking, and purely

Nothing here is a judgment about the change. It is the cost of a 61-commit branch waiting, and it
grows. The `showcases.csv` conflict also means the 53 rows of F-3 must be re-measured against the
new master before they are trustworthy.

  overridden nowhere** — against 174 new public functions and 54 new extension points. The questions
  [AR-EXT-MINIMAL-SURFACE](../../../rule/architecture.md#ar-ext-minimal-surface) and
  [AR-EXT-VIRTUAL-IS-A-PROMISE](../../../rule/architecture.md#ar-ext-virtual-is-a-promise) put to
  every new member; both rules postdate the first audit by eight days.

  | Class | uncalled | unoverridden |
  |---|---:|---:|
  | `Rfc6675Recovery` | 11 | 21 |
  | `TcpConnection` | — | 24 |
  | `TcpAlgorithmBase` | 5 | 14 |
  | `TcpSackRexmitQueue` | — | 11 |
  | `Tcp` | 1 | 11 |
  | `TcpSocket` | 8 | — |
  | `TcpCubic` | — | 7 |

  Spot-checked by hand: `Rfc6675Recovery::mayUndo`, `nextSeg`, `packetDelayed`, `prrCwndReduction`
  and others are **public, virtual, and called only from `Rfc6675Recovery.cc` itself**. They are not
  overrides — `ITcpRecovery` declares none of them. They are internal steps of the RFC 6675
  algorithm that happen to be public and virtual.

  This is the largest instance either rule has seen, and it is a question for the author, not a
  verdict: *who is `prrCwndReduction` for, and what would an override of `nextSeg` be trying to do?*
  Where the answer is "nothing outside this class", `private` and non-virtual says so. Where it is a
  sentence, the sentence belongs in the comment. A class designed as a base for future flavours
  legitimately has virtuals; 95 of them made by reflex is a different thing.

- **`IIeee80211Band` is not this branch's fault.** The interface gate reports it on the head and not
  on master, because master repaired it after this branch's base. A gate delta between a branch and
  a moved master needs this check every time; the finding is F-5's one class, not two.

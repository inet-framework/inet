## Findings

### F-1 — A shared queueing contract changes inside an 802.11 commit (PR-SPLIT-UPSTREAM, PR-MSG-GENERIC)

Commit `9463797904` *fix(ieee80211): make AP response transactions reliable* changes 8 files under
`src/inet/queueing/`:

| File | Change |
|---|---|
| `queueing/contract/IPacketQueue.h` | new `ICallback` interface, new `setPacketDropCallback()` |
| `queueing/contract/IPacketBuffer.h` | new `handlePacketDropped()` with a default body |
| `queueing/base/PacketQueueBase.h` | callback member and `notifyPacketDropped()` |
| `queueing/queue/PacketQueue.{h,cc}` | notification on overflow and on removal |
| `queueing/queue/CompoundPacketQueueBase.{h,cc}` | callback propagation to submodule queues |
| `queueing/buffer/PacketBuffer.cc` | `handlePacketRemoved` → `handlePacketDropped` |

The other 33 files of the commit are 802.11 code and its tests. A new capability of a contract that
every INET queue implements is therefore invisible in the subject line, and it cannot be reviewed,
reverted or cherry-picked on its own.

The cost is already visible in the pull request. Six review comments concern exactly these files,
and they raise a *generic* objection: "*I think the new packet drop signaling mechanism is redundant
with the existing one. See PacketDropReason and it's usage in Simsignals.msg*", and "*I think this
file should not exist, because it's whole functionality is covered by sending signals about dropped
packets*". That question belongs to the queueing contracts and to AR-OBS-SIGNALS. Because the change
has no commit of its own, the whole HT work now waits for a design discussion about a different
component.

**Fix.** Make the queueing change the first commit, with a rationale that holds for every queue user
— or remove the mechanism and use the existing drop signal, as the review proposes. The 802.11
commit then becomes small and reviewable on its own merit.

### F-2 — One commit, four decisions (PR-SPLIT-ONE-CHANGE, PR-SPLIT-DRIVEBY)

`9463797904` (41 files, +2507) contains:

1. the shared queueing capability (F-1);
2. a new 802.11 MAC contract `IFrameTransmissionCallback`, with the `Dcf`, `Hcf` and `Ieee80211Mac`
   wiring;
3. the AP transaction and AID ownership rules — the subject of the commit;
4. a wire-format fix in `Ieee80211MgmtFrameSerializer.cc`: the Association Response AID changes from
   `writeUint16Be(aid)` to `writeUint16Le(ASSOCIATION_ID_MARKER | aid)`, with new range validation
   and a matching decoder.

Item 4 is a drive-by. It is a standards-conformance fix with its own reason, it changes bytes on the
wire, and it belongs beside the earlier conformance commit `7b23a57d13`. A revert of the transaction
work would silently revert the encoding fix too.

The first two are true fixups: they make the reviewer read a wrong intermediate state, and they
break PR-SERIES-BUILDS in the middle of the series. The third is a real change, but its position
inverts the dependency direction.

### F-4 — The baseline commit is correct but stands in the wrong place (PR-SPLIT-BASELINE)

`942bf84671` *tests(fingerprint): accept intended WLAN trajectories* is exemplary in content: three
`.csv` files, no source file, and a message that explains all 37 baseline changes by cause, and that
states how a clean upstream build reproduced the old hashes. It is the best commit of the series.

Its position is the problem. It is commit 11 of 14, and two behavior-changing commits follow it. One
of them, `3be545a22f`, adds 64 selectable HT modes to the mode catalog, which can change rate
selection. The pull request description states the deferral: "*Fingerprint checks and updates were
intentionally deferred to the last commit of the PR. After making that commit, Devin signaled a new
issue…*". The baselines at the head are therefore unproven, and PR-SERIES-BUILDS may fail at the tip
and not only in the middle.

**Action before merge:** run the fingerprint suite at the head commit and move the baseline commit
last.

### F-5 — 47 files lose their trailing blank line (PR-SPLIT-WHITESPACE)

Every touched source file ends one line shorter, in 8 of the 14 commits, from
`queueing/contract/IPacketQueue.h` to `mgmt/Ieee80211MgmtSta.ned`. In a sample of 40 unrelated INET
source files, 37 keep the trailing blank line, so the branch changes a file-ending convention in 47
files as a side effect of unrelated work. Each file gets one extra hunk that the reviewer must open
and discard.

**Fix:** restore the blank line, or remove it tree-wide in one whitespace-only commit if the project
decides to change the convention.

### F-6 — Three subject conventions in one series (PR-MSG-SUBJECT)

`fix(ieee80211):` (7 commits), `feature(ieee80211):` (3 commits — conventional commits writes
`feat`), `tests(fingerprint):` (1 commit), and a bare `Fix …` with no area (2 commits). The canonical
form is `area: what the commit does`. All subjects stay inside the length limit and all name
behavior instead of files, which is right.

### F-7 — The pull request describes a feature, not the change (PR-REQ-TOPIC, -STORY, -ARCH)

The branch carries HT signalling, AP transaction reliability, a shared queueing contract, STA
lifecycle cleanup, PHY timing corrections and serializer conformance fixes. That is at least three
topics. The description gives the debug build command and 27/27 focused tests, but no exact test
commands, no fingerprint status, and no reading order for 14 commits. It never states that the
change touches `IPacketQueue` and `IPacketBuffer`, or that the new callback overlaps the existing
drop-signal mechanism — the one fact the reviewer needed first.

## Recommendation

Rewrite the series in this order, then re-run the fingerprint suite at the head:

1. `physicallayer/ieee80211: complete the n(mixed-2.4Ghz) mode catalog` — from `3be545a22f`.
2. `ieee80211: make PHY timing references explicit` — `c85de1c5f1` with the `PhyType` rename
   squashed in.
3. The queueing decision: either `queueing: notify the queue owner before a packet is dropped` as a
   commit of its own with a generic rationale, or the removal of the mechanism in favor of the
   existing drop signal (AR-OBS-SIGNALS). Resolve this first, because the rest depends on it.
4. `ieee80211: report frame transmission completion to the management layer` —
   `IFrameTransmissionCallback` with the `Dcf`, `Hcf` and `Ieee80211Mac` wiring.
5. `ieee80211: encode the Association Response AID little-endian with the 0xC000 marker`.
6. The existing 802.11 commits, with `81182d8a09` squashed into the commit that adds
   `handleReassociationFailure()`.
7. `tests: update the WLAN fingerprint baselines` — last, produced from the final tree.

Restore the trailing blank lines (F-5) and use one subject convention (F-6) during the rewrite.

## Rule gap found by this audit

PR-SPLIT-BASELINE says "*put the baseline commit directly after the commit that changes behavior*".
This series shows that the stronger form is needed: **no behavior-changing commit may follow the
baseline commit, and the baselines must come from the final tree.** The matching T3 check is "a
commit after the last `tests/**/*.csv` change touches `src/`".

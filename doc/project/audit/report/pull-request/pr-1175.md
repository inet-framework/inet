## Findings

### F-1 — Commit 1 is empty

**Rules:** [PR-SPLIT-ONE-CHANGE](../../../rule/pull-request.md#pr-split-one-change),
[PR-MSG-STANDALONE](../../../rule/pull-request.md#pr-msg-standalone). **Finding.**

`c647b2fa7b` — *"ieee80211: advertise AP HT discovery state from the MIB"* — changes no file. Its
tree is byte-identical to its parent's.

The cause is visible in master: `865aedcc0e`, of 2026-09-09, carries that exact subject and that
change. The author rebased this branch onto a master that had already taken the work, and git kept
the emptied commit instead of dropping it. `git rebase` drops such a commit by default; it is
retained by `--empty=keep`, by `cherry-pick --allow-empty`, or by a rebase that was resolved by
hand.

Two things make it worth removing rather than ignoring. **A commit that changes nothing is not one
change**, so the first thing a reviewer does — read one commit and ask whether it is right — has no
answer here. And its body describes real work in the present tense, so a reader of `git log` on the
merged branch will believe this branch did it. The same paragraph then exists twice in the history,
once attached to the change and once attached to nothing.

**What would close it:** `git rebase` the branch again and let the empty commit drop, or
`git rebase --onto` past it. Two commits remain, and both are real.

## A correction to this report's own instrument

The `--usage` pass that produces the Notes above had a defect until 2026-09-10, and it was found by
this audit. It split a function id on the **last** `::` to separate the owner from the name. A
qualified type in the argument list carries its own `::`, so
`Ieee80211Mib::setPrimaryChannel(int, const physicallayer::IIeee80211Band *)` was read as a function
named `IIeee80211Band *)`. That name matches nothing, so the function was reported **uncalled** —
while `Ieee80211MgmtApBase.cc` calls it twice.

Every function with a qualified argument type was affected, and `std::string` counts. The pass now
splits before the first `(`. The corrected counts, at the same bases as the original audits:

| Report | Uncalled | Tests only | Overridden nowhere |
|---|---|---|---|
| [#1172](pr-1172.md) | 6 → **4** | 6 → **6** | 13 → **10** |
| [#1173](pr-1173.md) | 6 → **4** | 4 → **4** | 15 → **12** |

Both reports are corrected. The lesson is the one the interface sweep already recorded: **a first
run of a new check is as likely to be reporting its own defect as the code's**, and the defect
produces plausible output. `setPrimaryChannel` was caught only because the finding was strange
enough to look at twice.

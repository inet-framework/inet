IEEE 802.11 aggregate preparation roles
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Custom implementations of the following IEEE 802.11 roles must be updated for ordered A-MPDU exchange preparation. The default implementations and in-tree test adapters implement these contracts.

* ``IMsduAggregationPolicy`` adds ``computeAggregateFrames(const std::vector<Packet *>&)``. The ordered candidates are borrowed. Return the policy-approved group without consuming sources or weakening its configured minimum count or length.
* ``IMpduAggregation`` adds an ``aggregateFrames`` overload taking ``MpduAggregationParameters``. It selects HT/VHT delimiter format and minimum member start distance. As with the existing aggregation role, the supplied input copies are consumed; retained originals must not be passed to it.
* ``IOriginatorQosMacDataService`` adds ``hasAMpduAggregation``, ``prepareFrames``, ``selectAmpduFrames`` and ``buildAmpdu``. Preparation returns owned previews and borrowed queue identities without extracting sources or allocating sequence values. Selection is an ordered prefix. ``buildAmpdu`` borrows originals/previews and uses copies through the aggregation role, returning an encoded packet whose OMNeT++ ownership the caller takes. Validate all previews before commitment; ``PreparedQosData::sequenceOffset`` denotes a predicted position relative to the one existing sequence owner.
* ``IRx`` adds ``prepareReceivedAmpdu``. It borrows a PHY-wrapped packet and atomically validates its complete structure before returning owned copies of FCS-correct members. Failure must not return a prefix or mutate NAV, peer, duplicate or reorder state. The receiving caller takes OMNeT++ ownership of returned packets before any refusal or deletion.
* ``IRecipientBlockAckProcedure`` adds ``processReceivedAmpdu``. The caller supplies accepted addressed DATA context after all members have been recorded, the current recipient agreement and computed response Duration. Submit one immediate Compressed Block Ack through the existing procedure callback; do not fabricate a received BAR or send a response per member.

``IQosRateSelection::computeResponseBlockAckFrameMode`` and ``IOriginatorQoSAckPolicy::getBlockAckTimeout`` now take ``Ptr<const Ieee80211TwoAddressHeader>`` for the eliciting frame. Support Basic/Compressed explicit BAR and implicit-BAR DATA as appropriate to the selected exchange. Preserve the configured timeout override and the PREDICT/RESPOND direction contract. A DATA query uses the selected or actual DATA mode; it is not an invented BAR-rate query.

The actual PHY vector has an ``ampdu`` fact distinct from ``singleMpdu``. A one-member selective retry retains the aggregate exchange, HT aggregate indication or VHT EOF0 and Compressed Block Ack. The EOF1 Normal-Ack single-member path remains separate. Neither indication alone says that a packet is currently bare MAC data: multi-member receive remains PHY-wrapped until atomic Rx preparation, while the radio removes a valid EOF1 envelope before ordinary capture and MAC receive.

For reconstructed member bytes, the receiving mesh role materializes the validated immutable mesh MAC header before generic observers or recipient service. Preserve its received-byte cache and FCS; do not infer the role from sender-only tags. MAC acknowledgment admission remains separate from native forwarding-body validation.

The VHT single-member helper takes the selected mode when computing or constructing the complete PSDU. It now fills exactly the existing raw-symbol capacity. Keep the pre-padding content, duration-equivalent pre-EOF prefix and complete PSDU extent distinct; a negotiated aggregate content cap is not a per-member cap or a generic 65535-byte VHT PSDU cap.

The new ``meshTerminalRecovery`` HCF notification carries a cleanup-complete ``MeshTerminalRecovery`` with reason ``DATA_RETRY_LIMIT`` or ``BAR_WAIT_LIMIT``. It is separate from DATA estimator samples. A valid BA zero can exhaust DATA retries without being a response timeout; leave ``MeshDataAttempt::terminalTimeout`` false for that case. Recovery-only BAR/BA must not resample DATA error or payload count. HWMP consumes the distinct terminal fact through its existing next-hop invalidation owner.
